# Sampling and the lm_head on GB10

Hardware for every own row: ASUS Ascent GX10 (NVIDIA GB10, SM121, compute capability 12.1, 48 SMs, 101,376 B opt-in shared memory per block, 102,400 B per SM, 128 GB unified LPDDR5X). TP1 rows ran on one node; TP2 rows on node-1 + node-2 over a direct RoCE link; TP3 rows on node-1 + node-2 + node-3. Unless a row says otherwise, own benchmark requests used temperature 0, thinking off, unique nonces and 512 forced output tokens, median of 3. Upstream code is quoted at vLLM `711fc55c10a2` (main, 2026-09-23) and at vLLM `487ecf187d3d` (the upstream commit under the own GLM 5.3 Flash TP3 lane; that lane's local overlays are not part of the upstream read), SGLang `f2a1366584e1`, llama.cpp `6e60f35608ec`, antirez/ds4 `0aaea5a238fb`, ExLlamaV3 `6b84a21b6f1e` and FlashInfer `e838a8585bdc` (v0.7.0). A code line says what upstream does at that pin, not what a given lane runs.

Two framing corrections run through the whole page. First, every GB10 "top-k kernel" defect on record is in a sparse-attention indexer (the block selector of Qwen 3.8 Flash Next's QSA or of GLM/DeepSeek-style DSA), not in the token sampler; the sampler has a separate, smaller GB10 history. Second, the widely repeated "TTFT 14 s to 1.4 s on a 20K prefix" is a prefix-cache result, not a top-k result (§4, §7).

## 1. What it is

After a model has processed its input, the last step of every forward pass turns the final hidden vector into one score per vocabulary entry. That step is the lm_head (the output projection to vocabulary), a single large matrix of vocabulary size times hidden size: about 248,000 x 5,120 for Qwen 3.8 27B, which is 2.5 GB in 16-bit form. Sampling (picking the next token from those scores) then applies temperature, top-k and top-p (keep only the likeliest tokens), min-p and penalties, and draws a token; greedy decoding (always the top score) is the special case at temperature 0. On a GB10 the two halves behave very differently. The sampler is cheap: in the only own kernel inventory it was about 0.0015% of GPU kernel time, and no public GB10 profile lists it as a cost. Its GB10 risks are hangs, crashes and silent path switches, not speed. The lm_head is expensive because decode on a GB10 is limited by how many bytes it can read per second, and the head is read on every forward pass that needs scores, including every draft pass of speculative decoding (a small model guesses tokens that the big model then checks). Shrinking what the drafter's head reads was the largest measured lm_head lever on the own lanes (+10% to +19% single-stream on one node). On multi-node tensor parallelism (the model split across nodes) each node holds a slice of the vocabulary, so the scores must be gathered across the network every step. And one quiet trap sits in front of all of it: a request that omits sampling settings is not greedy; the engine adopts the model's own recommended settings, so a benchmark that forgets to pin them measures sampled output. Related pages: [Speculative decoding on GB10](02-speculative-decoding.md), [Decode optimization on GB10: the bytes model](05-decode-optimization.md), [Inter-Spark communication](03-inter-spark-communication.md), [Prefill optimization on GB10](04-prefill-optimization.md), [Quality and correctness gates](21-quality-and-correctness-gates.md), [Profiling protocol](14-profiling-protocol.md).

## 2. How each engine does it

### vLLM

**Which sampler kernel runs.**
- Model Runner V2 is the default on CUDA whenever Triton is present and no unsupported feature is configured (`vllm/config/vllm.py:697-745` at `711fc55c10a2`). [Code-verified]
- V2 sampling order: logits processors (logit bias, penalties, bad words), then thinking budget, temperature, min-p, then top-k/top-p (`vllm/v1/worker/gpu/sample/sampler.py:65-76, 223-273`). [Code-verified]
- V2 runs the FlashInfer fused top-k/top-p sampler only when all four conditions hold for the batch: at least one request sets top-k or top-p; no request is greedy; no request carries an explicit `seed`; no request needs processed logprobs. Otherwise the whole batch takes Triton `apply_top_k_top_p` followed by the Triton `_gumbel_sample_kernel` (`sampler.py:283-352` at `711fc55c10a2`; `sampler.py:262-285` at `487ecf187d3d`). At temperature 0 the Gumbel kernel is a plain argmax, so it is also the greedy path (`gumbel.py:165-200` at `711fc55c10a2`; `gumbel.py:125-160` at `487ecf187d3d`). [Code-verified]
- `SamplingParams` resets top_p to 1 and top_k to 0 when temperature is below 1e-5 (`vllm/sampling_params.py:539-542`), so a generation_config top_p does not survive a temperature-0 request. [Code-verified]
- The legacy V1 `TopKTopPSampler` uses FlashInfer unless `VLLM_USE_FLASHINFER_SAMPLER=0` (default on, `vllm/envs.py:866-873`) and FlashInfer can JIT for the device; a per-request generator (`seed`) or an fp64 Gumbel request falls back to the native path; every FlashInfer call passes `deterministic=True` (`vllm/v1/sample/ops/topk_topp_sampler.py:77-126, 199-215, 276-303, 559-596`). The native path is Triton `apply_top_k_top_p_triton` plus exponential-noise sampling (`:439-449`), and current code checks FlashInfer JIT support up front and logs or raises a clear fallback (`_flashinfer_jit_unsupported_reason`, `:44-74`). [Code-verified]
- Speculative decoding rejects `min_p > 0` and `logit_bias`: "The min_p and logit_bias sampling parameters are not yet supported with speculative decoding" (`sampling_params.py:1036-1048` at `711fc55c10a2`; same check at `487ecf187d3d` `sampling_params.py:929`). [Code-verified]
- Penalties apply as logits processors before temperature (V2 `PenaltiesState`, `sampler.py:65-74`). [Interpretation] They are elementwise passes over `[rows, vocab]` plus a token-count scatter, so they cost about one more logits pass; no GB10 timing exists.

**Server defaults (the generation_config trap).**
- `generation_config: str = "auto"` (`vllm/config/model.py:332-338`). `get_diff_sampling_param` takes repetition_penalty, temperature, top_k, top_p, min_p and max_new_tokens from the checkpoint's `generation_config.json`, merged with `--override-generation-config`, and logs "Default vLLM sampling parameters have been overridden by ..." (`:1801-1846`). A `max_new_tokens` in that file becomes a server-wide output cap. The pin is `--generation-config vllm` or explicit request fields. [Code-verified]
- The default changed from unset to `auto` in PR #12622 (merged 2025-03-08). [Code-verified]

**lm_head and the TP gather.**
- `ParallelLMHead` is vocab-parallel. `LogitsProcessor.use_all_gather = current_platform.use_all_gather()`; the platform base returns True and `platforms/cuda.py` has no override, so every TP rank all-gathers and materializes `[rows, vocab]` (`vllm/model_executor/layers/logits_processor.py:91, 122-134`, `vllm/platforms/interface.py:1084-1086` at `711fc55c10a2`; `logits_processor.py:56, 84-96` at `487ecf187d3d`). [Code-verified]
- The gathered tensor has the dtype that the head's `quant_method.apply` returns. Neither pin casts to fp32 before the gather unless `head_dtype=float32` is set (hf-overrides, unquantized heads only; `logits_processor.py:136-178`); the V2 sampler copies to fp32 after the gather (`sampler.py:238-239`). [Code-verified]
- The `(value, index)` pair path (`get_top_tokens`, communication O(batch x 2 x tp)) is draft-only: its callers are speculative proposers and MTP heads; it requires `use_local_argmax_reduction` and raises if `draft_sample_method == "probabilistic"` (`vllm/v1/worker/gpu/spec_decode/speculator.py:303-326` at `487ecf187d3d`); at `711fc55c10a2` it is also incompatible with adaptive verification except for method `dspark` (`vllm/config/speculative.py:1580-1590`). The target verify pass always gathers full-vocabulary logits. [Code-verified]
- At main, DFlash2 drafts through `compute_candidates` -> `get_top_k_tokens` (candidate value/id gathers), not a full-vocabulary gather (`qwen3_dflash2.py`, `dflash2/speculator.py` at `711fc55c10a2`). DFlash2 is not in upstream `487ecf187d3d` (only `dflash`), so a lane built on that commit carries it as overlay code. [Code-verified]
- The vocab-parallel top-k helper uses FlashInfer radix `top_k(..., deterministic=True)`, described in code as "about twice torch.topk" (`logits_processor.py:29-53`). [Code-verified]

**Structured output.** The grammar bitmask (int32, `ceil(vocab/32)` words per row) is filled on the CPU; a fill thread pool is created when `max_num_seqs > 128`; grammar compilation is asynchronous (`vllm/v1/structured_output/__init__.py:62-78`). In V2 the bitmask is copied host-to-device on a side stream and applied in place by a Triton kernel adapted from xgrammar, one mask row per (request, draft position) (`vllm/v1/worker/gpu/structured_outputs.py:50-125`). The backend default is `auto` (`vllm/config/structured_outputs.py:21`). [Code-verified]

**Indexer top-k (the kernel people mean by "the SM121 top-k").** `persistent_topk` selects sparse-attention blocks for QSA and DSA models (the sparse-attention routes are on [Attention backends on SM121](06-attention-backends-sm121.md)). At `487ecf187d3d` it hard-fails when a cooperative launch would oversubscribe: "persistent_topk would oversubscribe and the FilteredTopK fallback requires >=128KB smem per block" (`csrc/libtorch_stable/topk.cu:135-145`). At `711fc55c10a2` the launcher falls back to `top_k_per_row_decode` instead when `max_smem_per_block < 128 KiB` (`topk.cu:152-160`), and `cooperative_topk` is excluded on capability family 120 (`vllm/model_executor/layers/indexer_topk.py:162-165`). [Code-verified]

**Flags and env vars.** `VLLM_USE_FLASHINFER_SAMPLER` (default on; 1 raises if FlashInfer cannot JIT, 0 forces Triton); `VLLM_USE_V2_MODEL_RUNNER`; `--generation-config {auto|vllm|<dir>}`; `--override-generation-config`; `--structured-outputs-config`; speculative-config `use_local_argmax_reduction`, `draft_sample_method`, `rejection_sample_method`; hf-overrides `head_dtype`.

**Defaults on CC 12.1.** FlashInfer sampler on (both pins ship FlashInfer newer than the hang fix: flashinfer-python 0.6.17 at `487ecf187d3d`, 0.6.18.post1 at `711fc55c10a2`, `requirements/cuda.txt`); generation_config `auto`; structured-output backend `auto`; indexer `persistent_topk` falls back to `top_k_per_row_decode` at main but hard-fails at `487ecf187d3d` unless an overlay routes around it. [Code-verified] Every inspected own vLLM boot printed "Using FlashInfer for top-p & top-k sampling", including the GLM EXL3 TP3 lane, and printed the generation_config override line. [Measured]

**Known-bad on CC 12.1.**
- FlashInfer at or below 0.6.13: multi-CTA radix top-k hang under sustained load (fixed in 0.6.14; both pins newer). [Community-measured]
- vLLM 0.20.0 (May 2026) with speculative decoding enabled: FlashInfer JIT rejected sm_121a, vLLM fell back to `apply_top_k_top_p_pytorch`, whose in-place `scatter_` crashed under CUDA-graph capture on requests with top_p or top_k set (issue #42745, closed as stale 2026-09-17). Current code uses Triton for the native path. [Community-measured] + [Code-verified]
- Grammar x reasoning parser x MTP on builds before PR #44993 (merged 2026-07-23): corrupt JSON or crashes (§4). [Community-measured]
- `persistent_topk` hard-fail on DSA models at `487ecf187d3d` unless an overlay routes GB10 to `top_k_per_row_decode`. [Code-verified]

### SGLang

- **Sampler.** An all-greedy batch uses `torch.argmax` (`python/sglang/srt/layers/sampler.py:181-196`). Otherwise logits are divided by temperature, softmaxed, and sampled with FlashInfer `top_k_top_p_sampling_from_probs(..., filter_apply_order="joint")`, or with `min_p_sampling_from_probs` after renormalization when min-p is set (`:357-395`); the pytorch backend is `top_k_top_p_min_p_sampling_from_probs_torch` (`:429`). The FlashInfer backend asserts that no per-request seed is set (`:358-360`). [Code-verified]
- **Backend default.** `sampling_backend` is `flashinfer` when FlashInfer is present, else `pytorch` (`arg_groups/overrides.py:967-975`); `--enable-deterministic-inference` forces `pytorch` (`:978-985`). [Code-verified]
- **Token-id sync.** Skipped by default; one all-reduce(MIN) of token ids per step is added when `SYNC_TOKEN_IDS_ACROSS_TP` is set or when any request carries a grammar (`sampler.py:649-664`). On multi-node TP that is an extra cross-node collective for every structured-output step. [Code-verified]
- **Server defaults.** `sampling_defaults = "model"` (`arg_groups/fields/serving.py:221-227`); `get_default_sampling_params` reads repetition_penalty, temperature, top_k, top_p and min_p from generation_config (`configs/model_config.py:2012-2037`). The pin is `--sampling-defaults openai` (temperature 1.0, top_p 1.0, top_k -1, min_p 0) or explicit request fields. [Code-verified] `--preferred-sampling-params` has no effect on `/v1/chat/completions`, and with an empty generation_config top_k resolves to -1 (issue #39096, open, GPU-free repro). [Community-measured]
- **Grammar backend.** Default xgrammar; choices xgrammar, outlines, llguidance, none (`arg_groups/serving_hook.py:217-221`). [Code-verified]
- **lm_head.** Vocab-parallel with an all-gather for plain TP. Two collective alternatives exist, both requiring DP attention: `--enable-dp-lm-head` (vocab-parallel over the attention-TP group, replicated under pure DP attention) and `enable_tp_lm_head_all_to_all` (default on only for PD-decode nodes with DP attention, dp > 1, tp == dp and attention-CP 1; settable explicitly whenever DP attention is on and tp == dp). `enable_fp32_lm_head` changes precision only (`layers/logits_processor.py:441-458, 876-900`; `arg_groups/overrides.py:1350-1395`). No GB10 use of the alternatives was found. [Code-verified]
- **Quantized-head guard.** `logits_processor.py` defines `should_apply_lm_head_quant_method` twice; the second definition (`:1278` onward) shadows the first and adds a `w4a16` branch. A quantized head is used only when the runtime tensors match its layout; this is the guard relevant to a dropped per-row head scale (§7). [Code-verified]
- **Draft head.** `--speculative-token-map` slices the draft head to a token subset and maps back through `hot_token_id`. [Code-verified]
- **Defaults on CC 12.1.** Every inspected own SGLang boot ran `sampling_backend='flashinfer'` and `grammar_backend='xgrammar'` and logged "Using default chat sampling params from model generation config" with the checkpoint's values. [Measured]
- **Deterministic inference on GB10.** About 11% throughput cost, and it forces the radix cache off, because the radix-preserving deterministic backends do not run on sm121 ("fa4 asserts out, triton fails during CUDA-graph capture"); measured and reported by TravisMeyers (hasso5703/dgx-spark-qwen38 issue #6, recorded in BENCHMARKS.md at `81ae2bf58394`). [Community-measured]

### llama.cpp and forks

- **llama.cpp.** Sampling runs on the CPU by default. The chain is penalties -> DRY -> top-n-sigma -> top-k -> typical -> top-p -> min-p -> XTC -> temperature (`common/common.h:261-271`); CLI defaults top_k 40, top_p 0.95, min_p 0.05, temp 0.80 (`:230-236`). Experimental GPU "backend sampling" is off for the target (`-bs`, `common/arg.cpp:2303-2308`) and on by default for speculative draft sampling (`common.h:332`). GBNF grammars apply in the CPU chain, with lazy grammars and triggers for tool calls (`common.h:273-276`). [Code-verified]
- **llama.cpp reads generation_config at conversion time.** The converter loads `generation_config.json` and writes `general.sampling.{top_k,top_p,min_p,temp,penalty_repeat,...}` (`gguf-py/gguf/metadata.py:71-90`; `conversion/base.py:1157, 1180`), and `common_init_sampler_from_model` applies those values unless the user set that sampler explicitly (`common/common.cpp:1213-1270`, called at `:1362`). Introduced by PR #17120 (commit `877566d512d0`, 2025-11-25); the repetition_penalty read was added by PR #27659 (commit `b3c3b96a139d`, 2026-08-24). This contradicts the answer in discussion #24024 (2026-06-20) that conversion "bakes in ... not runtime decoding defaults". [Code-verified] [Interpretation] llama.cpp's server defaults therefore depend on which converter produced the GGUF; explicit request fields still win.
- **Tensor split.** `-sm {none,layer,row,tensor}`, with `tensor` marked EXPERIMENTAL (`common/arg.cpp:2803-2808`). No vocab-gather cost for it is reported. [Code-verified]
- **No SM121 sampler path found as of `6e60f35608ec`; no GB10 sampler timing found.**
- **antirez/ds4.** Samples on the host CPU: `ds4_session_sample` runs `sample_top_p_min_p` over the float logits array (`ds4_server.c:13936-13958`); the DeepSeek V4 vocabulary is 129,280 and the `n_vocab` table at this pin also carries 154,880 and 248,320 shapes. Defaults temperature 1, top-p 1, min-p 0.05 (`ds4.h:59-61`; `docs/SERVER.md:46`); in thinking mode the defaults fill only knobs the client omitted, and a code comment says an explicit temperature 0 from a benchmark harness "must win" (`ds4_server.c:13940-13948`). Inside a DSML tool call the syntax tokens are forced to temperature 0 (`greedy_tool_syntax`, `:13950-13954`), which is how ds4 keeps tool syntax valid without a grammar mask. ds4 does not read generation_config. [Code-verified] GPU greedy top-1 fusion flags (`DS4_CUDA_GREEDY_SPLIT_TOP1`, `DS4_CUDA_OUTPUT_FUSED_TOP1`) measured "flat or slightly negative on this box" on one GB10 (antirez/ds4 #773). [Community-measured]
- **Entrpi/ds4-on-spark** (binary distribution at `99fb7b170528`, no engine source). The fork author describes a sampler override inside continuous batching for tools + thinking (§4) and a `DS4_SERVER_DEFAULT_TEMP` for requests that omit temperature (NVIDIA forum thread 376884, post #2). The env var is a fork-author claim that cannot be checked in source.
- **Anemll/dspark-vllm-gx10** (`081fda975417`). A vLLM fork focused on sparse MLA and MoE; it uses vLLM's sampler; no sampler change found. [Code-verified]
- **DS4X (wangshang23/ds4x, `a26a58d93777`).** An exact fused top-512 indexer kernel for sm_121a: an indexer kernel, not a sampler.

### ExLlamaV3 in vLLM

- **As deployed on GB10 lanes that use EXL3:** EXL3 weights run inside vLLM, so sampling, the generation_config default and the lm_head gather follow the vLLM section above. [Code-verified]
- **Native ExLlamaV3.** A fused sampler (`SS_Fused`, on unless `EXL3_FUSED_SAMPLER=0`) reduces top-k, top-p and min-p to one logit threshold from a deterministic fixed-point histogram, then draws with Gumbel-max (`exllamav3/generator/sampler/custom.py:17-19, 162-212`). `DefaultSampler` is min-p 0.08, temperature 0.8 (`presets.py:3-12`). generation_config is read only for EOS ids (`exllamav3/tokenizer/tokenizer.py:49-52, 159-160`); sampler defaults come from the caller. Native TP gathers logits to one output device (`OutputGather`, `exllamav3/modules/gather.py`). [Code-verified]
- **Unknown:** the output dtype of the EXL3 lm_head inside vLLM, which sets the bytes of the TP all-gather (§3, §8).
- **No SM121 sampler path or GB10 sampler timing found as of `6b84a21b6f1e`.** One X post (ViC305) gives native EXL3 at 58.8 tok/s on GB10 and names structured output as a reason to serve EXL3 through vLLM instead. [Community-measured]

### TensorRT-LLM (status)

TorchSampler is the only sampler. generation_config is opt-in (`generation_config='auto'` or `trtllm-serve --generation-config auto`); the default mode `trtllm` ignores it (TensorRT-LLM sampling docs, fetched 2026-09-23). [Code-verified] One three-node GB10 branch (NVIDIA forum thread 379060) compiles a top-8 Gumbel path, with temperature 0 reducing to argmax, and states sampling is "fail-closed in serving"; no sampled-vs-greedy timing.

## 3. What is different on GB10 / SM121

- [Code-verified] **Small shared memory breaks sparse-attention top-k, not the sampler.** With 48 SMs and 101,376 B per block, vLLM's indexer `persistent_topk` oversubscribes on long histories, and its FilteredTopK fallback needs at least 128 KB per block, so at `487ecf187d3d` the engine hard-fails; upstream main now falls back to `top_k_per_row_decode`. `cooperative_topk` is excluded on the SM12x family because its cluster launch is rejected (51/51 test cases fail on sm_121 per PR #55122) [Community-measured]. FlashInfer 0.6.18's deterministic FilteredTopK needs at least 131,072 B per SM and GB10 reports 102,400, so that backend does not start (PR #55872) [Community-measured].
- [Community-measured] **The FlashInfer multi-CTA radix sampler hang hit SM12x first.** The end-of-kernel reset race is architecture-independent (a commenter reproduced it on H100), but SM12x's 99 KB shared memory makes the CTA groups wider, so it surfaced there. The reset fix shipped in FlashInfer 0.6.14; a second hang class (free SMs fewer than `ctas_per_group`, "fix 2") was dropped from the PR and remains unfixed upstream (FlashInfer PR #3615).
- [Code-verified] **Toolchain history.** FlashInfer's JIT once rejected sm_121a, which pushed vLLM 0.20.0 onto a torch fallback that crashed under CUDA graphs; current vLLM checks JIT support up front and its native path is Triton.
- [Interpretation] **The lm_head is a bandwidth item.** Decode reads the whole head once per forward pass that needs scores. At the best published sustained GPU read of 231-234 GB/s on GB10 (antirez/ds4 #773 probe), a BF16 Qwen 3.8 27B head (248,320 x 5,120 x 2 B = 2.54 GB) costs about 10.9-11.0 ms per read, a packed NVFP4 head (about 0.72 GB with FP8 scales per 16 weights) about 3.1 ms, and a BF16 Qwen 3.8 Flash Next head (hidden 2,560, 1.27 GB) about 5.4-5.5 ms. Every speculative draft pass that uses the full head pays this again, which is why draft-vocabulary slicing works (§4). A community dual-node Flash Next contributor's byte budget, built from the checkpoint's safetensors headers rather than measured traffic, puts the lm_head reads (1 verify + 3 MTP drafts) at 2.36 of about 9.2 GiB read per step per GPU at TP2 (about 26%), with the target-logit all-gather at 0.99 MB per rank and 1 of 116 collectives per step (MiaAI-Lab/Qwen3.8-Flash-Next-Dual-DGX-Sparks PR #45, `autoresearch/RESULTS.md:311-316`, head `b08d24accac0`); the measured step there was about 50 ms.
- [Interpretation] **The multi-node gather is latency-bound at C1.** At about 8 decode rows the lm_head all-gather moves a few hundred KB to about 3 MB per step and is one of about 102 collectives per decode step on the own GLM TP3 lane (91 per target forward including the lm_head gather, plus about 11 for the drafter) [Code-verified count]. Its byte share matters only at high batch or with many full-vocabulary draft gathers. For the GLM TP3 target verify at 64 rows, the lm_head gather is about 17% of per-rank ring bytes with 16-bit logits (309,888 B per row; 12.6 of 72.6 MiB) and at most about 30% if logits were fp32 (25.2 of 85.2 MiB). Both are analytical; code shows no fp32 cast before the gather, so 30% is an upper bound.
- [Interpretation] **Host-side work runs on the GB10's Arm cores.** ds4 and llama.cpp sample on the CPU and vLLM fills grammar bitmasks on the CPU; the unified memory removes a PCIe copy, but none of this has been timed on GB10 (§8).
- [Code-verified] **SGLang's deterministic mode costs more on GB10.** The radix-preserving deterministic attention backends do not run on sm121, so determinism also disables prefix caching (§2) [Community-measured cost].
- [Community-measured] **SM count is 48, not 84.** FlashInfer's SM121 audit (issue #3170, open) states 84 SMs; device queries in vLLM PRs #55122 and #55872 and in the tonyd2wild crash forensics report 48 (`num_sms*occupancy=48`). Use 48. The same audit rates all sampling ops "Supported, arch-agnostic" and the clusters top-k path SM100-only, so SM121 uses a slower fallback.

## 5. Levers, ranked

Ranked by measured gain on the model families these lanes run, times how many lanes it applies to. Sampler-kernel levers rank low because the sampler is not a GB10 decode cost; the head's bytes and the sampling regime are.

1. **Slice the drafter's lm_head to a corpus-ranked vocabulary.** Applies to: vLLM (MTP draft vocabulary, community kit patch) and SGLang (`--speculative-token-map`) x models with a full-vocabulary MTP or NEXTN head (Qwen 3.8 Flash Next confirmed; any family with a 150K-250K vocabulary in principle) x TP1 and TP2. Gain: +10% to +19% single-stream on TP1 (essay +10%, code +19%) and +12.8% to +18.5% on TP2 with a 64K list [Measured]; +13.6% to +25.2% single-stream and +5.0% at 4 streams with a 65,536-row map on SGLang [Community-measured]; +11.7% with 32,768 ids on dual-node vLLM [Community-measured]. Cost: acceptance falls 3-6 points; a list build from a representative corpus; a launch flag. Risk: a list that misses identifiers loses heavily (8K corpus-only list: every metric worse, acceptance 36.43% [Measured]; 8,600 ids: -20% on code [Community-measured]); in vLLM a draft vocabulary is mutually exclusive with probabilistic drafting, so it fixes the draft method at greedy. Output is unchanged by construction (drafts are verified). Smallest falsifying experiment: same boot recipe, full head vs the list, frozen C1 code and prose fixtures at T=0 plus one T=1.0 arm; the lever fails if the T=1.0 arm loses more than the T=0 arm gains. Two lists are on record and no page compares them: the own 64K list measured 2026-09-05 on TP2 and on one node (§4; the packet does not state the exact row count, and the head arithmetic 0.16/0.59 × 248,320 ≈ 67K is consistent with 65,536), and the kit's 47,149-row code vocabulary that ran on the single-node lane in the 2026-09-11 MTP3/MTP4 screen ([MiaAI-Lab recipes](18-case-study-miaai-lab-recipes.md) §4). Which list the single-node lane runs now, and whether 47,149 replaced 64K by measurement or by adopting the kit, is open (§8).
2. **Pin the sampling regime, and match the draft sampling method to it.** Applies to: every engine x every model x every topology. Gain: avoids a 7.7% to 13.5% loss from greedy drafting at temperature 0.6 [Measured] and about 16% from greedy drafting under generation_config T=1.0 [Community-measured]; probabilistic DFlash2 drafting at T 0 vs 0.7 was within noise [Community-measured]. Cost: explicit request fields or a server flag (`--generation-config vllm`, `--sampling-defaults openai`). Risk: pinning the server changes production behaviour for clients that relied on the model's recommended settings; the two are separate decisions for benchmarking and for serving. Smallest falsifying experiment: one lane, frozen fixture, T=0 vs the generation_config regime, draft method greedy vs probabilistic (2x2), one boot per draft method; the lever holds if the mismatched cells lose more than run-to-run noise. Answers that are wrong at C8 but right serially are a correctness question, not a sampling one: see [Quality and correctness gates](21-quality-and-correctness-gates.md) lever 4.
3. **Keep the target head packed (FP4) where the engine can dispatch it, instead of a converted dense BF16 head.** Applies to: vLLM DFlash2 x Qwen 3.8 27B NVFP4 x TP2 (measured); other NVFP4 exports by extension. Gain: two-call decode +19% to +21% (92.01 -> 111.26-111.46 code, 36.43 -> 43.04 prose) [Measured], but a quantized-head dispatch patch changed with the head, so the head's share is not isolated; bytes-over-bandwidth predicts about 3.9 ms per head read per rank at TP2 [Interpretation]. Cost: a local patch in vLLM; about 3.2 GB of runtime memory saved per BF16 head avoided [Community-measured]. Risk: correctness. A loader that drops the per-row head scale produces a model that looks fast and agrees with its own drafter but samples nothing (§7); some engines need a dense head for correctness today (the own SGLang lanes run a BF16-head checkpoint with a validator). Smallest falsifying experiment: same image with the dispatch patch applied in both arms, head precision the only variable, C1 code and prose plus a logprob gate; the lever is falsified if the gap falls inside noise.
4. **Local argmax (or top-k candidate) reduction for draft tokens on TP.** Applies to: vLLM x MTP / proposer heads with greedy drafting x TP2 and TP3. Gain: +13.6% at concurrency 64 on 2x GB300 TP8, combined with a fused all-reduce, no clear change at batch 1 [Community-measured, not GB10]; -0.5% with a small draft vocabulary [Community-measured]; in production on the own Flash Next lanes since 2026-09-05 but never isolated [Measured config only]. Cost: a speculative-config flag. Risk: requires greedy drafting (raises with `probabilistic`); incompatible with adaptive verification except `dspark` at main. Smallest falsifying experiment: TP2 lane, flag on vs off, C1 and C8, one boot each; expect no C1 change and a measurable C8 change if the gather matters.
5. **Warm every sampler variant at boot.** Applies to: vLLM V2 lanes (any model, any topology) whose warmup does not issue greedy and seeded requests. Gain: removes a Triton JIT of `_gumbel_sample_kernel` inside a live request on every rank [Measured occurrence; spike size unrecorded]. Cost: a few warmup requests (greedy, sampled with top-k/top-p, sampled without, seeded). Risk: none known. Smallest falsifying experiment: boot, send one greedy request, grep the log for "Triton kernel JIT compilation during inference"; the lever is needed if the line appears and done if it does not.
6. **Route the DSA indexer off `persistent_topk` on GB10 and keep the batch budget below the crash point.** Applies to: vLLM x DSA-indexer models (GLM-5.3-Flash, DeepSeek V3.2-class) x any topology, on builds older than the upstream fallback. Gain: correctness past about 20-24K context (a 28.8K request that died completes) [Community-measured]; the own GLM TP3 lane's vendored overlay disables `persistent_topk` in the kpool indexer so long-history decode uses `top_k_per_row_decode` [Code-verified], and its launcher records a batch budget of 8,192 with long history as a 300K-context crash, so the budget stays at 7,168 or below [Historical diagnostic] (batch budgets and chunk sizing: [Prefill optimization](04-prefill-optimization.md)). Cost: a patch or a rebase onto upstream main. Risk: the fallback kernel's speed at very long history is unmeasured on GB10. Smallest falsifying experiment: one boot at batch budget 8,192 on a current build with the upstream fallback, a 300K-history decode; the budget cap is obsolete if it completes.
7. **Deterministic QSA indexer top-k instead of exact `torch.topk`.** Applies to: vLLM x Qwen 3.8 Flash Next (QSA) x TP1 (measured) and TP2. Gain: recovers the exact-topk prefill penalty, +21% to +28% cold prefill vs exact `torch.topk` [Community-measured]; flat vs stock in a 3-start server A/B [Community-measured]; do not claim it beats stock. Determinism needs four fixes together, and concurrent batches still diverge [Community-measured]. Cost: an unmerged PR (#55122). Risk: selection accuracy made no measurable difference on GLM agent turns (§4), so the case for it is reproducibility, not quality. [Proposed] for the own lanes (never run). Smallest falsifying experiment: first-token top-20 logprob repeat probe (6 prompts x 10 repeats, `max_tokens=1`) stock vs deterministic, same boot recipe; the lever is moot if stock is already bit-stable on the lane.
8. **Keep the FlashInfer sampler on (do not disable it on SM12x).** Applies to: vLLM and SGLang on GB10. Gain: +6% to +9% end to end vs the Triton sampler on small models at concurrency 32 [Community-measured, B200/H200]; on GB10 decode the sampler is a small share of a 9 to 60+ ms step, so the expected gain is at most a few percent [Interpretation]. Cost: none. Risk: the dropped co-residency hang class in the FlashInfer multi-CTA radix top-k has no GB10 report either way (§8); the reset-race hang is fixed in the pinned versions. Smallest falsifying experiment: `VLLM_USE_FLASHINFER_SAMPLER=0` vs default, sampled (T 1.0, top-k 20, top-p 0.95) at C1 and C8, nsys trace; the lever is irrelevant if the sampler kernels stay under 1% of the step in both arms.
9. **Thinking off (or a grammar fix) for strict structured output, and a separate gate for it.** Applies to: vLLM and SGLang x reasoning models x MTP or DFlash2. Gain: correctness: strict JSON with default thinking failed on both engines and passed with thinking off [Measured]; on builds before PR #44993 removing any one of grammar, reasoning or MTP fixed output [Community-measured]. Cost: no reasoning inside structured calls. Risk: a mask-cost change is unmeasured on GB10 (§8). Smallest falsifying experiment: the same strict JSON gate on a build that carries PR #44993, thinking on vs off; the thinking-off rule can be relaxed if both pass 10/10.
10. **Sharded lm_head alternatives (SGLang DP LM head, TP LM-head all-to-all).** Applies to: SGLang x DP-attention deployments only; not to plain multi-node TP, which is how the own lanes run. Gain: TPOT -2.1% to -3.5% on B200 DP8 [Community-measured, not GB10]. Cost: DP attention. Risk: DP attention changes KV and memory layout on a 128 GB node. [Proposed]. Smallest falsifying experiment: none worth running until a lane uses DP attention.
11. **Quantized drafter lm_head (NVFP4 or FP8).** Applies to: MTP drafters with a full BF16 head. Gain: none measured; bytes predict a cut similar to the draft-vocabulary slice without changing acceptance [Interpretation]. Cost: no published patch for the relevant checkpoints. Risk: draft quality. [Proposed]. Smallest falsifying experiment: quantize the drafter head only, same list, C1 code and prose, acceptance recorded.
12. **SGLang deterministic inference.** Applies to: SGLang x any model where reproducible multi-turn evaluation matters. Gain: removes multi-turn greedy variance [Community-measured]. Cost: about 11% throughput and, on GB10, the radix cache [Community-measured]. Risk: losing prefix reuse on agent traffic costs far more than 11%. Use for evaluation boots only. Smallest falsifying experiment: the 34-task multi-turn harness with the flag on vs off, radix state recorded.

## 6. Protocol

The protocol an agent runs for any change that touches sampling, the lm_head, the drafter's head, the indexer top-k, or structured output. It is grounded in §4 and in the incidents in §7. See also [Profiling protocol](14-profiling-protocol.md), [Speculative decoding on GB10](02-speculative-decoding.md) and [Quality and correctness gates](21-quality-and-correctness-gates.md).

**Preconditions (fleet rules, all mandatory).**
- No memory overcommit: at least 8 GiB MemAvailable on every rank before a start, and a warm floor of at least 5 GiB on every rank after the longest qualified prefill.
- One variable per boot. A head swap, a draft-vocabulary change, a draft-method change and a warmup change are four boots, not one.
- Stop traffic when MemAvailable falls below 4 GiB on any rank; preserve the engines.
- Clean window: no co-tenant GPU work, builds or other benchmarks, and the lane's owner has agreed to the downtime.
- Restart A/Bs with the image and recipe pull skipped, so both arms run identical bits.
- Never restart a serving gateway or front-end as part of the experiment; if the change needs one, stop and hand that step to the operator.
- All [entry-page](README.md) rules apply, in particular: greedy logprob probe after every relaunch; discard the first request and warm every shape; unique nonce at token 0 with zero cached tokens asserted from the usage block; every rank at the same clock cap with no latched rank; the selection line on every rank; ≥3 reps with a closing A/B/A; MemAvailable every 1-2 s and zero NV_ERR_NO_MEMORY/Xid; no reboot without per-node permission. For this page that means in particular the same clock cap on every rank, `MemAvailable` sampled every 1-2 s, a nonce per prompt and a closing A/B/A.
- Read the boot log before measuring and copy three lines into the packet: the sampler backend line ("Using FlashInfer for top-p & top-k sampling" or SGLang `sampling_backend=`), the generation_config default line, and the speculative-config line (draft method, local argmax, draft vocabulary).

**Gates before any speed number.**
1. Logprob gate after every relaunch: an 8-token greedy probe with `logprobs`; top-1 must sit in O(-1) to O(-20) with runners-up a few nats below. A top-1 of 0.0 with runners-up near -30,000 means the head is broken and every number from that boot is void.
2. On a QSA or DSA model, run the first-token top-20 logprob repeat probe (6 prompts x 10 repeats, `max_tokens=1`) before trusting any T=0 comparison. If it is not bit-stable, report T=0 results as distributions, not single values.
3. Warm every sampler variant the clients can send (greedy, sampled with top-k/top-p, sampled without, seeded if any client seeds), then grep the log for "Triton kernel JIT compilation during inference" and record whether it appears.

**The change.** Exactly one variable per boot.

**Measurement.**
- Every request sends explicit `temperature` (and top_p/top_k if sampling). Never send `seed` on vLLM unless seeding is the variable (it moves the batch off FlashInfer). Never send `min_p` or `logit_bias` to a vLLM lane with speculative decoding (the request is rejected).
- Decode: frozen C1 code and prose fixtures, forced 512 output tokens, median of 3, plus C4 or C5 when the change touches batching or collectives. Report the request temperature and the draft sampling method with every decode number.
- If the change is a sampling regime: run a 2x2 of request temperature (0 vs the generation_config regime) by draft method (greedy vs probabilistic), one boot per draft method.
- If the change is a head or draft-vocabulary change: record acceptance per step alongside tok/s; a speed gain with an acceptance drop is expected, an acceptance jump on a head change is a red flag (§7).
- If the question is the sampler's share: one nsys decode trace at C1 and C8, greedy vs T 1.0 / top-k 20 / top-p 0.95, plus a `VLLM_USE_FLASHINFER_SAMPLER=0` arm. On multi-node TP add an NCCL-traced decode step to read the lm_head all-gather's real size and share.
- If the change touches structured output: the same prompt set with and without `response_format` at C1 and C8, thinking off, speculation on, plus a strict-JSON correctness gate with thinking on and off. Label counting prompts ("count from 1 to 200") as prompt types, never as structured output.

**Record (packet fields).** Engine, version and pin; the one-line diff; the three boot lines above verbatim; head dtype and format; draft vocabulary size and list source; draft method and rejection method; `use_local_argmax_reduction`; request sampling fields actually sent; logprob-gate result; determinism-probe result (QSA/DSA models); JIT line present or absent; per-arm decode tok/s, acceptance, prefill tok/s; trials per arm; per-rank MemAvailable minimum.

**Pass gate.**
- Logprob gate passes on every boot.
- Decode change stated at the pinned temperature and draft method, outside run-to-run noise (at least 3 reps, and larger than the spread of the control).
- No acceptance jump without an explanation; an acceptance rise with a head change blocks promotion until the head is checked.
- Strict-JSON gate passes 10/10 in the configuration that will serve structured calls.
- No JIT line in the log after warmup.
- Memory: warm floor at least 5 GiB on every rank.

**Rollback.** Revert the one changed line (head checkpoint, draft list, speculative config, warmup script or server flag), boot with the pull skipped, re-run the logprob gate and one frozen C1 fixture, and confirm the numbers match the recorded baseline within noise.

## 7. Anti-patterns and known-bad

- [Measured] **A dropped lm_head scale looks like an excellent lane.** SGLang logged `Parameter lm_head.weight_scale not found in params_dict`, built an unquantized head from the FP8 weight and discarded the per-row scale. Greedy top-1 logprob was 0.0 with runners-up near -30,000; every request became hard argmax whatever its temperature; the drafter shared the same broken head, so acceptance looked superb (p90 8.0 on T=1.0 prose). A whole control arm and a quality benchmark were withdrawn. High acceptance on a broken head measures self-consistency, not quality. Gate: logprob probe after every relaunch; a launch validator refuses a head that carries `weight_scale` where the engine cannot apply it.
- [Measured] **Paramless requests are not greedy.** Every inspected boot adopts the checkpoint's generation_config (T 1.0, top_k 20, top_p 0.95 on Qwen; T 1.0, top_p 0.95 on GLM). A benchmark or agent client that omits sampling fields measures sampled output. [Community-measured] Two paramless requests diverged within 15 tokens on GB10 (hasso5703); since vLLM PR #32723 (merged 2026-01-22) `vllm bench serve` no longer forces temperature 0, so community numbers after that date are sampled unless `--temperature=0` was passed.
- [Community-measured] **The reverse trap: a harness that ignores generation_config.** lm-eval's vLLM backend did not apply a checkpoint's repetition_penalty 1.1 and GSM8K fell from 51.56 to 34.38; an export that dropped the sampling keys made vLLM sample the full vocabulary at T=1 and output collapsed. Record what the server actually applied, not what the model card says.
- [Measured] **Greedy drafting under a sampled request temperature.** Greedy drafting at request temperature 0.6 cost 7.7% to 13.5% on a DeepSeek V4 Flash TP2 lane and was reverted; a community Flash Next run lost about 16% at T=1.0 [Community-measured]. Match the draft method to the production temperature and report both with every decode number.
- [Measured] **Blaming sampling for a speculative-decoding collapse.** A production MTP acceptance collapse was first suspected to be sampling; probes showed greedy, paramless and temp-0.7 requests at 2.95-3.00 accepted of 3. The cause was YaRN not reaching the drafter. Probe acceptance under greedy and default sampling before blaming the sampler.
- [Community-measured] **Attributing "TTFT 14 s -> 1.4 s at a 20K prefix" to the SM121 top-k kernel.** That figure is a prefix-cache hit after a `block_size` fix in a community recipe (blazux README, commit `4b723de2`). The deterministic top-k's measured value is recovering the exact-topk prefill penalty (+21% to +28% vs exact `torch.topk`), and against stock it measured flat in a controlled A/B.
- [Code-verified] **Reading indexer top-k bugs as sampler bugs.** The GB10 top-k crash (DSA `persistent_topk` past about 20-24K context) and the GB10 T=0 nondeterminism (QSA `persistent_topk` slot order) are sparse-attention indexer kernels. Changing sampler settings does not touch them.
- [Community-measured] **Expecting the deterministic indexer kernel alone to make greedy reproducible.** Alone it left 330 disagreeing positions against 333 with no fix; four fixes together reached 0, and concurrent batches still diverge. The PR author withdrew the "fixes greedy" framing (vLLM PR #55122, 2026-09-21).
- [Community-measured] **Turning on the FlashInfer deterministic DSA top-k backend on GB10.** It needs at least 131,072 B of shared memory per SM and GB10 has 102,400; the engine does not start (PR #55872).
- [Historical diagnostic] **Batch budget 8,192 with long history on a DSA-indexer GLM recipe.** The vendored launcher records it as a 300K-context `persistent_topk` shared-memory crash; budgets of 7,168 and below were kept.
- [Measured] **A warmup that covers only the default sampling shape.** The GLM TP3 boot warmup covered `top_p=0.95` but not the `top_k=0, top_p=1.0` Gumbel path, so the first greedy request compiled `_gumbel_sample_kernel` inside a live request on all three ranks.
- [Measured] **Strict JSON with thinking on, and structured auxiliary calls without a token cap.** `response_format=json_object` with default thinking returned malformed JSON on vLLM and empty content at a 128-token cap on SGLang; title-generation calls that carried `response_format` without `max_tokens` or thinking-off made cancellation look broken (2026-08-27 Flash Next production maintenance record).
- [Measured] **Quoting "structured" tok/s from decode tables as a grammar result.** The "structured" rows in the fleet decode tables are a counting prompt; the upstream benchmark README says "Prompt types, not grammar / schema."
- [Community-measured] **Grammar x reasoning x MTP on vLLM builds before PR #44993.** Corrupt JSON (`{{"name"`, `{"{"city":"Paris"}`), "Failed to advance FSM", silent HTTP 500s and an engine crash across xgrammar, guidance and outlines; removing any one of the three avoided it. Check the build's base commit before running strict structured output with reasoning and speculation.
- [Community-measured] **Assuming full logits land on one rank in vLLM.** A community write-up and a research synthesis said so; the code says every CUDA rank all-gathers `[rows, vocab]` (`use_all_gather()` returns True with no CUDA override).
- [Community-measured] **Assuming llama.cpp never reads generation_config.** A 2026-06 discussion answer said so; since PR #17120 (2025-11-25) the converter writes `general.sampling.*` from it and the runtime applies those values unless the user overrides them.
- [Community-measured] **Sending `seed` or `min_p` to a vLLM speculative lane in a benchmark.** A seed moves the whole batch off the FlashInfer sampler; `min_p` and `logit_bias` are rejected with speculative decoding [Code-verified].
