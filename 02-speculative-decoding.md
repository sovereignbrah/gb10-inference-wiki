# Speculative decoding on GB10, per engine

Hardware for every own row: ASUS Ascent GX10 (NVIDIA GB10, compute capability 12.1, 128 GB unified memory). Single-node rows ran on one box; TP2 rows on node-1 + node-2 over a direct RoCE link; TP3 rows on node-1 + node-2 + node-3 in a RoCE triangle. Unless a row says otherwise, numbers are decode tok/s per stream, "agg" means aggregate across concurrent streams, and "forced-512" means 512 output tokens with EOS ignored, temperature 0, thinking off, a cold nonce per repetition, median of 3. Code lines are quoted at these pins: vLLM `711fc55c10a2` (v0.30.0 era), SGLang `2909f84e3b2f` (v0.5.20 era), llama.cpp `6e60f35608ec` (b11147), ExLlamaV3 `6b84a21b6f1e` (v1.5.1). The own lanes run older builds and forks, so a code line says what upstream does now, not what a given lane runs.

"k" and "acceptance" are not one knob across engines. Read every number on this page through this table.

| term | vLLM | SGLang | llama.cpp | ExLlamaV3 (native) |
|---|---|---|---|---|
| k | `num_speculative_tokens` = drafts per step | `--speculative-num-draft-tokens` = verify window: for DFLASH it equals the block size (drafts + 1 anchor); for DSPARK it is gamma + 1 | `--spec-draft-n-max`, clamped to the drafter's trained block | `num_draft_tokens`, default = the drafter's `default_draft_size` (DFlash2: block size − 1) |
| acceptance | `/metrics`: accepted / proposed draft tokens (a per-draft-token rate, 0..1), plus per-position counters | "accept length" includes the +1 bonus token; accept rate = (accept length − 1) / (num draft tokens − 1) | tokens per step from the server `timings` block | engine counters |

## 1. What it is

Speculative decoding lets a cheap guesser, the drafter (a small helper predictor), propose the next few tokens, and then has the full model check all of them in a single pass, keeping the longest run of correct guesses plus one token of its own. In principle it changes only how many tokens come out of each expensive pass, not what the model says; in practice quantized targets are often not bit-identical under speculation, though answers usually are (§7). The drafter can be a separate small model (a draft model, EAGLE-3, or the block-diffusion drafters called DFlash and DFlash2), extra prediction heads trained into the main model (MTP, multi-token prediction heads, and its DeepSeek relative DSpark), or no model at all (n-gram or "prompt lookup", which copies from text already in the context). On a GB10 this is usually the biggest single decode lever because producing one token means streaming the model's active weights out of memory at roughly 273 GB/s nominal, and the chip's compute sits mostly idle while it waits; checking eight guessed positions reads the same weights once, so it costs about the same as producing one token. Own measurement: a verify step took 138 ± 3 ms whether it accepted 1.55 or 7.95 tokens [Measured]. Speed is then roughly accepted tokens per step divided by step time. It stops paying when guesses are wrong (free-form prose accepts far less than code or counting: 95.9% vs 49.6% at the same setting on one own lane [Measured]), when many users share the batch and the verify pass is no longer nearly free, when a mixture-of-experts model has to read the union of experts that every checked position routes to, and when a multi-node split pays a network round trip per step. Acceptance, the share of guesses kept, is a property of the workload, never a single number. See also [Decode optimization on GB10: the bytes model](05-decode-optimization.md) and [CUDA graphs and launch overhead on GB10](01-cuda-graphs-and-launch-overhead.md).

## 2. How each engine does it

### vLLM

Selection and methods. One JSON flag, `--speculative-config`, carries `method`, `model` (the drafter), `num_speculative_tokens`, `draft_tensor_parallel_size`, `draft_sample_method` and the n-gram and rejection options. Methods at the pin: `ngram`, `medusa`, `mlp_speculator`, `draft_model`, `suffix`, `custom_class`, `eagle`, `eagle3`, `extract_hidden_states`, `dflash`, `ngram_gpu`, `dspark`, and 26 named MTP model types plus the generic `mtp` (vllm/config/speculative.py:36-86, MTP list :39-66). Rejection sampling is `standard | synthetic | block`. Draft sampling defaults to `greedy`; `probabilistic` uses full draft logits "at the cost of additional GPU memory" (:601-607). [Code-verified]

- DFlash2. Landed upstream in PR #52816 (merged 2026-08-21, b389ac29) and ships in v0.28.0; the `dflash2` speculator directory exists at tag v0.28.0 and not at v0.27.1. Model Runner V2 routes `method: dflash` to `DFlash2Speculator` when the draft architecture is `DFlash2DraftModel` (v1/worker/gpu/spec_decode/__init__.py:17-28). The drafter's grouped convolution is built with `block_size = 1 + num_speculative_tokens` (model_executor/models/qwen3_dflash2.py:255). Its weights do not depend on the block size, so k is fixed into the drafter module at load: a k change needs a relaunch, not new weights. [Code-verified]
- Quantized target heads. The PR branch refused targets whose LM head was quantized; released 0.28.0 dispatches the head through its quant method (`LogitsProcessor._apply_head`), so a stock NVFP4 checkpoint with an FP8 head works, and no such guard string remains in v1/worker/gpu/spec_decode/dflash2/speculator.py. [Code-verified] Earlier GB10 recipes needed a BF16-head conversion or a patch (madeye; gitcommit90 removes "one overly broad type guard"). [Community-measured]
- MTP and multi-module drafts. When `num_speculative_tokens` exceeds the drafter's `n_predict` it must be divisible by it (speculative.py:1486-1498). DeepSeek V4.1 DSpark sets `n_predict` to `dspark_block_size` (:1440-1455); Qwen3-Omni DSpark requires `num_speculative_tokens == block_size` (:179-183). [Code-verified] On GB10 this surfaces as Step-3.7-Flash MTP k in {3, 6, 9} with 3 fastest (forum 373163) and DeepSeek V4 DSpark k at least the DSpark block of 5 (hazyumps). [Community-measured]
- n-gram. Model Runner V2 has no n-gram speculator: `init_speculator` dispatches hidden-state extraction, DFlash/DFlash2, DSpark, Gemma-4 MTP, multi-module MTP, MTP and EAGLE, and raises `NotImplementedError` otherwise (v1/worker/gpu/spec_decode/__init__.py:8-58). The Dynamic SD examples in the docs set `VLLM_USE_V2_MODEL_RUNNER=0`. [Code-verified]
- Load-dependent k. Dynamic SD takes `num_speculative_tokens_per_batch_size` as `[start_bs, end_bs, K]` rows; the docs say "tested with Eagle, Eagle-3, and DFlash", FULL CUDA graphs only on Model Runner V2, and it switches itself off under data parallel (PR #32374, merged 2026-06-14). Adaptive Verification (`enable_adaptive_verification`) is DSpark with a confidence head only, requires full CUDA graphs, rejects `--enforce-eager`, LoRA and pipeline parallel, and profiles step cost at startup against an 8,192-token synthetic context, overridable with `VLLM_ADAPTIVE_VERIFICATION_PROFILE_CONTEXT_LEN` (PR #47808, merged 2026-08-12). [Code-verified] (docs in the repo at the pin)
- CUDA graphs. Capture sizes are rounded up to multiples of (k + 1) (`adjust_cudagraph_sizes_for_spec_decode`, config/compilation.py:1536), so the reachable row counts are C x (k + 1) for C live sequences. FlashInfer attention reports `UNIFORM_BATCH` graph support on SM90 and the SM12x family when its trtllm/XQA kernels can serve the model's head layout (v1/attention/backends/flashinfer.py:977-1010), which allows FULL decode graphs with speculation there; the downgrade to PIECEWISE (compilation.py:1444-1462) now applies only below `UNIFORM_BATCH`. [Code-verified] A June build forced PIECEWISE for FlashInfer + MTP on GB10 and mis-estimated graph memory (issue #44740). [Community-measured] Topic page: [CUDA graphs and launch overhead on GB10](01-cuda-graphs-and-launch-overhead.md).
- Compile cache. `SpeculativeConfig.compute_hash` hashes auxiliary hidden-state use, the draft config and layer ids but not `num_speculative_tokens` (speculative.py:613-657). [Code-verified] Issue #53366 (open): sweeping DFlash2 k = 7 / 9 / 11 on a shared cache directory crashes with `AssertionError: expected size 7==9` depending on launch order; the workaround is a separate `VLLM_CACHE_ROOT` per k. [Community-measured]
- Drafter placement. `draft_tensor_parallel_size` is validated to 1 or the target TP (speculative.py:1709-1740) and a draft parallel config is built (:1760-1785), but the EAGLE, EAGLE-3, MTP and DFlash proposers build the drafter from the target's config with only kernel, attention and KV-dtype overrides (`_DRAFT_VLLM_CONFIG_OVERRIDES`, :377-384; V1 v1/spec_decode/llm_base_proposer.py:1266-1318; V2 eagle/utils.py:73-88 and dflash/utils.py:16-50). Only the separate `draft_model` method (which requires draft TP = target TP) and the V2 DSpark loader consume the draft parallel config. For DFlash, DFlash2, EAGLE-3 and MTP the drafter is therefore sharded by the target's TP degree whatever the flag says. [Code-verified] This is contested by the text of RFC #53673 (open), which says draft TP 1 under target TP N "works today" as replication (§8). Pipeline parallel places eagle3 / dflash / dspark drafters on the last stage for opted-in targets (PR #50514, merged 2026-09-05). [Code-verified]
- Measurement. `/metrics` counters are engine-wide. `--per-request-spec-decode-metrics` takes three levels (`none`, a per-request aggregate middle level, and `detailed`) and adds `metrics.speculative_decoding` (mean acceptance length, draft acceptance rate, acceptance histogram, and with `detailed` per-step accepted and drafted arrays) to each n=1 response (PR #48915, merged 2026-08-20; first release v0.29.0). [Code-verified]
- Defaults on CC 12.1. Nothing in the speculative config is SM121-specific. What decides behaviour on GB10 is the attention backend's graph support (above), the greedy draft-sampling default, and the missing V2 n-gram path. [Code-verified] A community report on 128 GB boxes: `gpu-memory-utilization` at 0.90 or above fails the startup free-memory check, 0.895 passes (MiaAI-Lab issue #179). [Community-measured]

### SGLang

Selection. `--speculative-algorithm` takes `DFLASH`, `UNO`, `DSPARK`, `EAGLE`, `EAGLE3`, `FROZEN_KV_MTP`, `STANDALONE` or `NGRAM`, plus plugin-registered algorithms; `NEXTN` is a reserved alias for EAGLE (srt/speculative/spec_info.py:39-47; spec_registry.py:183). There is no Jacobi "lookahead" algorithm. Other flags: `--speculative-draft-model-path`, `--speculative-num-draft-tokens` (verify window), `--speculative-num-steps`, `--speculative-eagle-topk`. [Code-verified]

- DFLASH (arg_groups/speculative_hook.py:248-400). Forces `speculative_num_steps = 1` and `speculative_eagle_topk = 1`; `--speculative-num-draft-tokens` is the block size and must equal `--speculative-dflash-block-size` if both are set; when unset it is inferred from the draft config, else 16; DP attention is rejected except on NPU; `pp_size` must be 1; `max_running_requests` resets to 48 when unset. [Code-verified]
- DSPARK (:685-740). `speculative_num_draft_tokens` must equal gamma + 1, where `--speculative-dspark-block-size` is gamma. So an own "k=5" DSpark lane runs 6 draft tokens and block 5. [Code-verified]
- NGRAM (:1115-1160). CUDA, CPU or XPU; default 12 draft tokens; mixed chunked prefill disabled. [Code-verified]
- UNO (:401-563). CUDA, FA3 for both prefill and decode, TP = PP = 1, no DP attention or context parallel, no rejection-sampling flag, mixed chunk off; linear mode is B / K / V = draft tokens / 1 / draft tokens with steps 1 and topk 1, and a tree mode exists (topk > 1). [Code-verified] FA3 is a Hopper kernel family [Interpretation]; no SM121 path found as of `2909f84`.
- Adaptive depth. Only EAGLE / EAGLE3 with topk 1; each candidate step tier owns CUDA graphs captured for its reachable padded batch sizes, and switching tiers is a reference swap after the current round, never an online recapture. [Code-verified] (docs page advanced_features/adaptive_speculative_decoding, fetched 2026-09-23, not a pinned commit)
- Drafter placement. The draft worker is built from the same `server_args` as the target, so it has the target's TP; a separate draft TP group exists only under DP attention (speculative/draft_worker_common.py:61-100; spec_utils.py:750-754; eagle_worker_v2.py:266-273; dflash_worker_v2.py:385-405). The DFlash greedy is TP-safe: it all-gathers each rank's local max and argmax over the TP group (dflash_worker_v2.py:124-180). The draft-TP-1 RFC (#14343) closed without a serving flag and the remote-drafter PR (#22272) closed unmerged. [Code-verified] Pipeline parallel: a tracking issue (#39634, open) reports non-last ranks skipping auxiliary hidden-state capture. [Community-measured]
- GB10 specifics. Qwen3.8-Flash-Next needed PR #36649 (merged 2026-08-27) to admit sm_121 to the QSA trtllm-gen sparse decode gate; before it graph capture aborted and the server never became ready (issue #36558). NEXTN rejects more than 4 draft tokens on that model (`_require_chain_speculation`, issue #36796). Hybrid KDA/mamba targets under DFLASH need 1 + D mamba state slots per running request; a tight static fraction silently capped concurrency at 2 until `--max-mamba-cache-size 40 --mamba-ssm-dtype bfloat16` (issue #36889). DFlash2 and DSpark were incompatible with YaRN beyond 262K on the build at commit c14312a66 (forum 380732). [Community-measured]
- Defaults on CC 12.1. Nothing in the speculative arguments is SM121-specific; the GB10 differences are the kernel gates, shared-memory limits and state-slot sizing above. [Code-verified]
- Measurement. SGLang packs 2 to 4 tokens per streamed event under DFlash2; set `--stream-interval 1` or count `usage.completion_tokens` (forum 380732). [Community-measured]

### llama.cpp and forks

Upstream. `--spec-type` takes `none`, `draft-simple`, `draft-eagle3`, `draft-mtp`, `draft-dflash`, `draft-dspark`, `ngram-simple`, `ngram-map-k`, `ngram-map-k4v`, `ngram-mod` and `ngram-cache` (common/speculative.cpp:33-45). The draft GGUF is `-md`; depth is `--spec-draft-n-max / --spec-draft-n-min`, with `--spec-draft-p-min`; n-gram-mod uses `--spec-ngram-mod-n-match / -n-min / -n-max`; the old `--draft / --draft-max / --draft-min` are removed stubs (common/arg.cpp). DFlash landed in #22105 (2026-06-28), DSpark in #25173 (2026-07-28), DeepSeek V4 MTP + DSpark in #25784 (2026-08-02), DFlash2 selector support in #27816 (2026-08-27; detected from `selector_top_k > 0` in the draft metadata), and a multimodal DFlash decode fix in #28587 (2026-09-10). The draft length is clamped to what the drafter was trained for: DFlash yields at most block size − 1 drafts, anchor-first DSpark a full block, and a larger `--spec-draft-n-max` is clamped with a warning (common/speculative.cpp:998-1006). [Code-verified] An own DFlash2 run on a block-8 drafter (a pre-merge PR build) found requested k = 8 and k = 16 both ran as 7 [Measured]; tying that run to this code line is [Interpretation].

- Multi-node. No multi-node or tensor-split drafter: an HTTP proxy between two servers was closed (#23982), and DFlash / DFlash2 with `--split-mode tensor` assert on multi-GPU (#27833, #28777, open). [Community-measured]
- Defaults that bite. `draft-simple` with the default `p-min` 0.00 collapsed acceptance to 0.070 (issue #25908, Vulkan). `ngram-cache` kept a slot's previous n-grams across requests because `begin()` was a no-op (issue #27852, x86_64, open). [Community-measured]
- ds4 native fork (Entrpi, llama.cpp-derived, DeepSeek V4 Flash 2-bit GGUF, 3-layer DSpark drafter). Continuous batching by default; DSpark is engaged only for solo streams (`DS4_DSPARK_MAX_NLIVE=1`), so concurrent traffic rides plain batched decode; a per-request "yield quench" turns speculation off when realized acceptance cannot pay for the verify step; kill switches `DS4_DSPARK_QUENCH=0`, `DS4_DSPARK_MAX_KV=N`, `--no-dspark`; the guard is recalibrated per model identity (2.16 for the 0731 weights), and drafters are generation-matched to their target. [Community-measured] (README @ 99fb7b1)
- Defaults on CC 12.1. The speculative defaults are architecture-independent; GB10 evidence is single-node and GGUF-quantized, and DFlash gains on MoE GGUF targets have been smaller than in vLLM (§4). [Code-verified] for the defaults; [Community-measured] for the gains.
- Anemll's GX10 image is a vLLM 0.25 DSpark port for TP 2, not a llama.cpp fork; see vLLM. [Community-measured]

### ExLlamaV3 in vLLM

Native engine (outside vLLM). Supports a draft model, DFlash (added 2026-04-23), DFlash2 (PR #334, merged 2026-09-20, in v1.5.1), MTP drafts and n-gram drafting (`ngram_match_min`). `num_draft_tokens` defaults to the drafter's `default_draft_size` (DFlash2: block size − 1). `dynamic_draft_tokens` cuts the verified window with an online-calibrated confidence and, for DFlash, keeps the fixed diffusion block cost (generator/generator.py:70-176; architecture/dflash2.py:205-235). Qwen3.5-family MTP drafting asserts a single sequence per job (generator.py:739). DFlash2 refuses tensor-parallel targets ("the selector needs top-k logits", dflash2.py:225-228); DFlash v1 drafts are `supports_tp: False` but can attach to a TP target through an argmax dispatch (dflash.py:255-314). No multi-node ExLlamaV3 speculative path found as of `6b84a21`, and no SM121-specific speculative default. [Code-verified]

EXL3 through vLLM (the vllm-exl3 plugin and the GLM / DeepSeek EXL3 forks). Speculative flags, CUDA-graph behaviour and drafter placement are vLLM's, at whatever vLLM base the fork carries. The GLM 5.3 Flash EXL3 forks add their own DFlash2 KV-group patches (drafter sliding-window layers slot-shared into MLA pages, or a dedicated draft ring) and fork environment variables `DFLASH_TOKENS`, `DFLASH_DRAFT_TP` and `GLM53_ADAPTIVE_K*` (Entrpi COMPARISON.md; MiaAI-Lab issue #179). [Community-measured] MiaAI-Lab PR #48 states that `DFLASH_DRAFT_TP` is passed through as the upstream `draft_tensor_parallel_size` field [Code-verified per the PR text; the fork source was not re-read at a pin]. Given the vLLM placement code above, a "rank-0-only drafter" setting on these forks may never have executed on rank 0 [Interpretation]; an own verifier stage read the GLM TP3 fork and found the drafter built on every TP rank under the target's parallel config, TP-sharded through heads padded to 36 / 9 so they split evenly three ways [Code-verified; per-rank shape dump still owed].

- Adaptive k on the GLM EXL3 forks is an EMA over a k-set (own lanes run {2, 4, 7}, k max 7). The hooks take the batch minimum, so any structured-output request, or any request with fewer than 4 observations, pins the whole batch at k = 7. Adaptive k trims target verification rows only; the DFlash2 drafter still runs one forward per step at its load-time block. A k-set change also changes which physical row counts are graph-captured and which fall back to stock MoE kernels, so k-set A/Bs are confounded unless kernel dispatch is re-profiled. [Code-verified]
- vLLM base. The own GLM TP3 runtime is built on vLLM `487ecf187`, which is not descended from PR #51538 (the padded-slot top-k fix; merge base b908a21f, 93 commits behind the fix). Only the EXL3 overlay could carry the fix, and that is unverified. Until it is, capturing every reachable row count is a stability requirement on that lane, not only a speed choice (§3, §7). [Code-verified]
- Measured through vLLM with EXL3: Qwen3.8-Flash-Next MTP k = 2 and k = 3 beat no draft at 4K, and k = 4 wedged after `torch.compile` (vcruz305); DeepSeek-V4-Flash-Vision DSpark k = 3 (vcruz305). Rows in §4. [Community-measured]

## 3. What is different on GB10 / SM121

- [Measured] Verify is bandwidth-bound on dense targets. Own single-node SGLang DFlash2 on a Qwen 3.8 27B NVFP4 target: 138 ± 3 ms per verify step for accept lengths 7.95 down to 1.55 at 27K to 84K depth (2026-08-19, "single-node uncensored DFlash2 campaign audit"). [Interpretation] The packet's byte table gives ~20 GB read per step including a 3.85 GB draft and states ~206 GB/s achieved (76% of 273 GB/s nominal) with no stated step time; over the packet's 130.8 ms KV-excluded base step, 24.22 GB implies 185.2 GB/s, and 20.09 GB over the measured 138 ms step is ~146 GB/s, so the 206 GB/s figure is not reproducible from the packet and every GB/s figure here is [Interpretation]. The flat step time is the load-bearing fact.
- [Community-measured] Verify is not free on every engine. On the native ds4 fork one DSpark verify step (1 committed + 4 draft rows) costs 2.03 to 2.08 plain decode steps from 2K to 64K, rising to ~2.4 at 240K to 515K; stated law: speedup = tokens per step / ~2.05, break-even at ~51% draft acceptance (Entrpi, measured at v0.4.1).
- [Community-measured] On sparse MoE targets, verifying k positions activates the union of the experts those positions route to. Qwen3.8-Flash-Next (top-10 of 512 experts) in llama.cpp on one GB10: a vocabulary-matched 0.8B draft model gave no speedup (mean accepted length 2.88, decode unchanged at ~23 tok/s) (0xBakeer). [Interpretation] Built-in MTP heads avoid a second model but not the expert-union cost; no own spec-on/off sweep isolates it. See [MoE dispatch on GB10](08-moe-dispatch.md).
- [Measured] The drafter lives in the same 128 GB as the OS, the target and the KV cache. A padded DFlash2 drafter KV layout reserves ~36.7 KB per token against ~2 KB used, over (sliding window − 1 + concurrent batches x batch budget) tokens rounded up to 64-token pages, not over the batch budget alone: the packet gives ~3.3 GiB at a 2,048-token batch budget and ~7.4 GiB at 7,168, which capped one TP2 lane's context at 900K (2026-09-08 "E4 adaptive-k / FP8 / ablit / batch A/B"); on a hybrid target K16 doubled the recurrent-state working set (2026-08-24 "DFlash2 K sweep"). See [Memory management on a unified-memory GB10](11-memory-on-unified-memory.md).
- [Community-measured] Shared memory per block is 101,376 B on SM121. The DSA tilelang kernel at an 8-token verify shape needed 169,984 B and was retuned to block_I 32, 1 stage, 128 threads (forum 381703); EAGLE without tuned MoE configs needed 147,456 B and the server did not start (GLM-4.7-FP8, TP4; forum 359960).
- [Community-measured] A speculative batch padded up to a larger captured FULL graph hung the GPU on SM121 sparse MLA: GLM-5.3 native FP8, `FLASHINFER_MLA_SPARSE_SM120`, 8 GB10 TP8, MTP k = 1, capture sizes 1, 2, 4, 8: three sequences made 6 rows, padded into the 8-row graph, and never returned; capturing 1..8 fixed it (26.1 tok/s at 6 rows), as did PIECEWISE or eager. The owner was vLLM's persistent top-k reading a padded slot's context length −1 as uint32, fixed in PR #51538 (merged 2026-08-15); the reporter ran 168 h on full capture with 3,364 / 3,364 probes passing (flashinfer issue #5015, closed 2026-09-19). [Code-verified] Current vLLM rounds capture sizes to multiples of k + 1, which is why sizes 1, 2, 4, 8 at k = 1 left 6 rows uncaptured.
- [Code-verified] FULL decode graphs with speculation are allowed with FlashInfer on SM12x at the pin only when trtllm/XQA can serve the head layout; otherwise vLLM downgrades to PIECEWISE. [Community-measured] FlashInfer + MTP k = 2 hit an illegal memory access on a GQA-16 model on GB10 where Triton attention served 22.4 tok/s (vLLM #37754, open).
- [Community-measured] SM121 had to be admitted explicitly to a sparse-attention decode gate (SGLang PR #36649) before speculative graph capture on Qwen3.8-Flash-Next worked at all.
- [Code-verified] Uno in SGLang requires FA3 and TP 1; no SM121 run found. [Community-measured] The published vllm-uno image is AMD64-only (brntech README), so Uno on GB10 runs only as the vLLM PR #55947 overlay.
- [Code-verified] TensorRT-LLM (status only; docs fetched 2026-09-23): DFlash `attention_backend` VANILLA runs on any architecture, TRTLLM is SM100 / SM103 only and FA4 SM90 only, so VANILLA is the documented SM121 option. The NVIDIA Spark playbook shows EAGLE-3 and draft-target on one and two Sparks with no tok/s table. No GB10 TensorRT-LLM speculative number was found.
- [Community-measured] Over a slow interconnect speculation divides the per-token collective cost by the accept length but cannot remove it: MiniMax-M3 TP3 over 1 GbE issues ~120 small all-reduces per token and EAGLE-3 (accept length ~2.6) gave only 6 -> 7.5 tok/s; on 200G RoCE single-stream was ~10.5 tok/s and stated compute-bound (tonyd2wild). [Measured] Own GLM EXL3 DFlash2 acceptance at 64K and 120K did not change from TP2 to TP3 (0.39-0.51 and 0.39-0.46). See [Inter-Spark communication over DAC](03-inter-spark-communication.md).
- [Community-measured] Cross-node PIECEWISE capture of a host-staged NCCL all-reduce faults at capture end on 2 GB10 without GPUDirect RDMA; eager is stable (vLLM #46253, open).

## 5. Levers, ranked

Ranked by evidenced gain on own lanes first, community evidence second. Every gain band is per stream at C1 unless stated.

1. **Turn speculation on with a matched drafter** (native MTP heads, or a DFlash2 / DSpark drafter trained for this target and quantization family). Applies to: all four engines x dense and MoE x 1x / TP2 / TP3. Gain: +54% prose and +95% coding, +61% at C8 aggregate for MTP-4 on a GLM NVFP4 TP2 lane [Measured]; code +138% and prose +16% for MTP k = 2 -> DFlash2 k = 16 on a Qwen 27B TP2 lane [Measured]; 3.7x code and 1.8x prose over autoregressive on a Q3 GGUF in llama.cpp [Measured]; 1.10x code and 1.04x prose over the ds4 fork's own plain decode [Community-measured]; zero for a separate small draft model on a sparse MoE target [Community-measured]. Cost: drafter weights and draft KV out of the unified-memory budget; boot-time k geometry. Risk: mismatched drafters (a cross-quant drafter crashed at 15.8% acceptance [Measured]; BF16-trained EAGLE drafts on NVFP4 targets accepted ~6%, scottgl9 [Community-measured]); speculation-linked wrong answers under concurrency (SGLang #36548) [Community-measured]. Smallest falsifying experiment: one boot family, spec off vs on, prose + code + 64K + C4 fixtures, 3 reps; the lever fails if prose falls below spec-off beyond spread.

2. **Choose k per workload and depth, starting from the drafter's trained block.** Applies to: every engine; the answer is specific to model x drafter x engine x workload. Gain: fixed k = 3 beat k = 7 on every real-shaped cell of a GLM EXL3 TP2 lane (coding +20%, prose +19%, 64K +31%) and lost only count-to-200 [Measured]; k = 10 beat k = 8 on a single-node SGLang Qwen 27B lane (code +14.6%, prose +7.0%) [Measured]; the abliterated Qwen 27B variant peaked at its trained block K8 [Measured]; vLLM k = 8 beat 12 / 16 on prose while k = 16 won code [Measured]; DeepSeek V4.1 DSpark k = 5 vs k = 3 traded code +12% for C8 −14% [Measured]; K = 16 at 131-135 tok/s vs K = 7 at 73-74 on edit-heavy work only [Community-measured]. Deeper k lost repeatedly: MiniMax num_spec 5 < 3, Hy3 spec-2 −30%, K = 24 < K = 16, Qwen3-Coder-Next EAGLE-3 steps 5 < 2, llama.cpp DFlash n-max > 4 [Community-measured]. Cost: one relaunch per k (the vLLM DFlash2 drafter is built for 1 + k). Risk: stale compile cache across k (vLLM #53366); boot-blocked geometry (MTP5 on a 1,616-token attention page [Measured]); a k change moves captured row counts. Smallest falsifying experiment: two boots, trained block − 1 vs the candidate, each class 3 reps, fresh compile cache per k.

3. **Adaptive k, with CUDA-graph capture covering every reachable row count.** Applies to: vLLM EXL3 GLM forks (EMA k-set), vLLM Dynamic SD (upstream; EAGLE / EAGLE-3 / DFlash), SGLang adaptive (EAGLE / EAGLE3, topk 1), ExLlamaV3 `dynamic_draft_tokens`. Gain: a bundle containing adaptive-k {2, 4, 7} took structured 36.6 -> 66.2 and coding 22.9 -> 30.8 over fixed k = 3, with no component attribution [Measured]; {2, 4, 7} beat {3, 5, 7} and {2, 4, 6} by 15-18% at 64K, confounded by dispatch geometry [Measured]. Cost: a longer capture list and startup time. Risk: batch-minimum policies pin the batch at k max whenever one structured request is live [Code-verified]; on a vLLM base without PR #51538 an uncaptured padded replay can hang on SM121 sparse MLA [Community-measured]. Smallest falsifying experiment: force the k-set to {7}, {4} and {2} in three windows of one boot through the fork's override file and compare per-class tok/s against the EMA window [Proposed].

4. **Trim the MTP draft vocabulary.** Applies to: vLLM MTP heads with large vocabularies (a 248,320-row head) x 1x and TP2. Gain: +13-19% single stream on a Flash Next TP2 lane (prose +14.1%, code +12.8%, C1 +18.5%) even though acceptance fell 58.59% -> 52.18%, because the draft head read fell 0.59 -> 0.16 GiB per rank (lm_head and draft-vocabulary mechanics: [Sampling and the lm_head](12-sampling-and-lm-head.md)) [Measured]; +19% code and +10-23% prose on a single node [Measured]; an 8K corpus-only list lost everywhere (36.43% acceptance) [Measured]. Cost: a list build and a relaunch. Risk: identifiers outside the list; tool-call correctness not separately gated. Smallest falsifying experiment: full vs trimmed list on one boot family with an identifier-heavy code fixture and a tool-call echo test.

5. **Match the drafter's context extension to the target.** Applies to: any drafter with its own config (MTP rebuild in vLLM, DFlash2 draft checkpoints) x any topology at depth. Gain: acceptance at ~300K from 0.00 to 1.14 / 2 (~2x decode at depth) [Measured]; removed a device-side assert at 264,384 tokens [Measured]. Cost: an edited copy of the draft config. Risk: none measured beyond the edit. Smallest falsifying experiment: a 250K+ probe with per-position acceptance after every relaunch.

6. **Draft sampling method.** Applies to: vLLM DSpark (and any vLLM drafter) x sampled targets. Gain: probabilistic over greedy by 3.5-6.4 tok/s at 8K / 32K under temp 0.6 (single runs, ±2 noise) [Measured]. vLLM's default is `greedy` [Code-verified]. Cost: extra GPU memory for cached draft logits [Code-verified]. Smallest falsifying experiment: 3-rep A/B at temp 0 and temp 0.6.

7. **Size the batch budget for draft slots.** Applies to: vLLM DSpark when the engine warns that draft slots do not fit the budget. Gain: 32K 44.7 -> 47.4, 8K within noise (single runs) [Measured]. Cost: prefill step memory. See [Prefill optimization on GB10](04-prefill-optimization.md).

8. **Drafter precision and calibration.** Applies to: SGLang and vLLM DFlash2. Gain: a calibrated NVFP4 drafter over BF16, code +6.7%, prose +4.1% (screen) [Measured]. Risk: a drafter trained on a different quantization of the target (above). Smallest falsifying experiment: combined, repeated comparison with the chunk setting it was screened beside.

9. **Enough recurrent-state slots for hybrid targets.** Applies to: SGLang DFLASH x hybrid KDA / mamba models x TP2. Gain: c8 aggregate 47.3 -> 78-80.3 tok/s once slots stopped capping concurrency at 2 [Community-measured]; bf16 SSM states cost ~6% single stream. Cost: 1 + D state slots per running request. See [Linear attention and hybrid layers on SM121](07-linear-attention-and-hybrid-layers.md).

10. **Load-aware verification.** Applies to: vLLM Dynamic SD and Adaptive Verification, DSpark's prefix scheduler, the ds4 fork's quench (serving load and concurrency: [Serving agent workloads](22-serving-agent-workloads.md)). Gain: none measured on GB10 [Proposed]; DeepSeek reports 60-85% faster per-user generation than MTP-1 at matched aggregate throughput in its own data-center deployment (arXiv 2607.05147 §5; vendor-measured, not GB10) [Community-measured]; the ds4 quench keeps adversarial prose at 0.95-0.97x plain where always-on speculation fell to 0.72x [Community-measured]. Smallest falsifying experiment: spec off vs on vs Dynamic SD at C1 / 4 / 8 / 16 on one lane (the U1 curve in §8).

11. **n-gram / prompt lookup for copy-heavy work.** Applies to: llama.cpp (`ngram-mod`), SGLang `NGRAM`, vLLM V1 only. Gain: ~70 tok/s for a one-line file change vs ~22 on prose [Community-measured]. Cost: none in memory. Risk: repeated-prompt inflation (§7), tool-call corruption at `prompt_lookup_min = 2` (vLLM #40875), cross-request leakage in `ngram-cache` (#27852) [Community-measured]; the own vLLM attempt failed to launch on Model Runner V2 [Measured].

12. **Drafter tensor-parallel placement.** Applies to: vLLM TP2 / TP3 lanes (the collective cost per step is on [Inter-Spark communication](03-inter-spark-communication.md)). Gain: none measured. The drafter is built on every TP rank on the own GLM TP3 fork and upstream [Code-verified]; a per-rank shape dump is still owed. Upstream `draft_tensor_parallel_size` is inert for EAGLE / EAGLE-3 / MTP / DFlash [Code-verified]; MiaAI-Lab PR #48 publishes draft TP 2 as "holding" against the rank-0 setting (structured 65.1, prose 27.1) without the comparator in the PR body [Community-measured]; an own upstream-cited prediction of +1.7-4.5% single stream for draft TP 1 was never run, blocked by memory headroom [Historical diagnostic]. Smallest falsifying experiment: a per-rank module-shape and memory dump at boot under each setting; A/B only if the shapes differ [Proposed].

## 6. Protocol

This is the protocol for any speculative-decoding change on a GB10 lane. It follows the fleet rules on the entry page and the incidents in §4 and §7. Kernel attribution is in [Profiling protocol](14-profiling-protocol.md); correctness gates in [Quality and correctness gates under optimization](21-quality-and-correctness-gates.md).

Preconditions.
- All index rules apply (see [the entry page](README.md)), in particular: at least 8 GiB MemAvailable on every node before a start, a 5 GiB warm floor measured after the longest qualified prefill, and traffic stopped below 4 GiB; a greedy logprob probe after every relaunch; discard the first request and warm every serving shape before timing; a unique nonce at token 0 with zero cached tokens asserted from the usage block; every rank at the same clock cap with no latched rank; the selection or configuration line read on every rank; at least 3 repetitions with a closing baseline (A/B/A); MemAvailable sampled every 1-2 s with zero NV_ERR_NO_MEMORY or Xid lines; no reboot or power cycle without per-node permission; correctness gates from [Quality and correctness gates](21-quality-and-correctness-gates.md) before any speed number. For this page: discard the first request after every k or k-set change, and read the clock cap on every rank.
- No memory overcommit: at least 8 GiB MemAvailable on every node before a start, a 5 GiB warm floor while serving, and stop all benchmark traffic at 4 GiB MemAvailable on any node. KV pin raises stay at or under 1.5 GiB per boot. Drafter weights and draft KV count against these numbers; swap is not headroom.
- One variable per boot. A restart for an A/B skips the image pull, so the only difference is the variable under test.
- Clean window: poll running requests and any client shim's in-flight count before each pass; idle-gate every counter delta; discard and label any pass that overlaps outside traffic (one own base pass was discarded for ~90 overlapping requests).
- Never restart a client gateway; the engine restart is the operator's step, and a gateway restart is the operator's decision. Never `pkill -f` a pattern that also matches your own shell.
- Context extension (YaRN or rope overrides) baked into both the target and the draft checkpoint configs, not passed at runtime.
- Record the build: engine commit; whether it contains vLLM PR #51538 (padded-slot top-k fix) and PR #48915 (per-request metrics); the compile cache directory.

Change. Exactly one of: speculation method on / off, drafter checkpoint, k, adaptive k-set, draft sampling method, drafter precision, draft vocabulary list, draft TP, batch budget for draft slots.
- For a k or k-set change: use a fresh `VLLM_CACHE_ROOT` (or equivalent) per k; recompute the capture list so it contains C x (k + 1) for every reachable C and k; on forks with a profiled MoE dispatch policy, re-profile before the A/B or label the A/B confounded.
- Re-read the live engine configuration after editing launch scripts (a sed edit of escaped JSON once did nothing).

Run.
1. Boot. Record the resolved speculative config, the capture list, KV pool tokens, boot warnings about draft slots or geometry, and MemAvailable per node.
2. Logprob gate: one greedy probe with known top-1 logprob magnitude; a top-1 near 0.0 with runners-up tens of thousands below means a broken head, and every acceptance number after it is invalid.
3. Fixtures, one class at a time, 3 repetitions (5 for a maintainer fixture), cold nonce at token 0: counting / structured, fresh code, copyable code edit, prose (hash-map and essay), tool call, depth 64K and 120K (and the lane's maximum), C1 / C4 / C8 (C16 where slots allow). Report forced-length and natural-EOS runs separately.
4. Count tokens from `usage.completion_tokens`, never from stream events; on SGLang set `--stream-interval 1`.
5. Acceptance: per class, per position where the engine exposes it, state the convention (per-draft-token rate vs accept length with bonus). On vLLM v0.29+ use `--per-request-spec-decode-metrics detailed` and tag requests by class; otherwise use idle-gated counter deltas per class.
6. Correctness: a greedy four-item ordering battery at C1 and C8, spec on vs spec off on the same config (the SGLang #36548 shape).
7. After promotion: a live metered window of at least 30 minutes; compare engine acceptance with the prose fixture. A live number far below the bench (the own 0.00-at-depth incident) is a failure.

Record (packet fields): engine and image commit; method; drafter id, revision and precision; k or k-set; draft sampling method; draft TP as configured and as executed (per-rank module shapes); capture list; KV pool tokens; per class: tok/s median and spread, acceptance per draft token, per position, accept length (convention stated), tokens per verify step, TTFT; C4 / C8 aggregate and per-stream; forced vs natural EOS; minimum MemAvailable per node; logprob gate result; correctness battery result; contamination flag and discarded passes.

Pass gate. Prose, code and both depth cells at or above baseline beyond repetition spread (single-run differences under ~10% support nothing); C8 aggregate not worse unless the trade was accepted before the run; logprob gate passes; correctness battery identical spec-on vs spec-off; no device-side asserts, hangs or NVIDIA allocation errors; MemAvailable at or above the 5 GiB warm floor on every node; live-window acceptance consistent with the bench classes.

Rollback. Revert the one variable, restart with the pull skipped and the previous compile cache directory, confirm the resolved speculative config matches the baseline, then run the logprob gate plus one prose and one code fixture; both must match the baseline within spread before the lane serves again.

## 7. Anti-patterns and known-bad

- [Measured] A broken target head inflates acceptance. A checkpoint loaded without its lm_head weight scale made the target and a head-sharing drafter agree on the same corrupted argmax: accept-length p90 hit the block ceiling (8.0, rate 1.0) on temperature-1.0 prose and decode rose ~60%. All numbers from that arm were withdrawn (2026-08-19 campaign audit). Gate every relaunch on a greedy logprob probe. See [Sampling and the lm_head on GB10](12-sampling-and-lm-head.md).
- [Measured] Runtime context-extension overrides did not reach the drafter in two vLLM paths: MTP gave zero acceptance at depth while short probes were perfect (2026-08-18 diagnostic), and DFlash2 hit a device-side assert at 264,384 tokens (2026-08-20 k=16 packet). [Measured] The opposite leak exists in SGLang: launch-time override arguments applied to both target and draft crashed a draft config that lacks `text_config`. Bake the extension into both checkpoints.
- [Measured] One acceptance number is meaningless: counting 95.88% vs prose 49.62% at the same drafter and setting, and decode followed acceptance (2026-09-16 packet). A count-to-N "structured" headline is a k = 7 artifact of a maximally predictable prompt.
- [Measured] Short benchmark probes can show perfect acceptance while production-depth traffic accepts nothing; watch live acceptance after every change.
- [Historical diagnostic] Composite claims assembled from different protocols (tok/s from one packet, acceptance from another) were withdrawn.
- [Measured] [Interpretation] Forced-length (EOS-ignored) fixtures and count-to-N prompts overstate general speed; community headline numbers produced that way were excluded from own comparisons. [Community-measured] One serve-bench guide requires forced 1,024-token continuations to be reported apart from natural stops (Infatoshi BENCHMARK.md). [Interpretation] No source isolates `ignore_eos` itself as changing acceptance; it changes which tokens dominate the average.
- [Community-measured] Repeated identical prompts under n-gram drafting climbed 59.8 -> 169.0 tok/s by the third run (43.2 -> 100.3 in chat) against an honest 43; a copy task read 171 tok/s at one `max_tokens` and 52 at another; single-run spread was 6.5% (llama.cpp) and 6.9% (vLLM) (0xBakeer). Loops past 256K inflated DSpark acceptance, and a YaRN re-anchor "gain" cost ~15x per step (habr 1055792).
- [Community-measured] Counting stream events instead of tokens under-reads multi-token accepts: ~2.2x on EAGLE (BTankut), ~2.5x on DSpark (habr), and a forum decode-share figure was corrected from 7.1% to 1.7% (forum 378890).
- [Measured] Dashboard instantaneous speculation gauges read 2-3x the sustained per-request decode (92-139 tok/s bursts vs ~40 sustained).
- [Measured] [Code-verified] A recipe comment said "drafter on rank 0 only" on a TP3 vLLM build; the source builds the drafter on every TP rank and TP-shards it through padded 36 / 9 heads. A "shard the drafter" proposal was struck as already implemented. Verify placement from source plus a per-rank shape dump, not from comments.
- [Code-verified] Changing the adaptive k-set also changes which physical row counts are graph-captured and which fall back to stock MoE kernels; k-set A/Bs are confounded without re-profiling. Adaptive k trims only target verification rows, never drafter cost.
- [Measured] Draft count must fit other geometry: an attention page vs the speculation ring (MTP5 unbootable: ring 12 must divide a 1,616-token page), max-draft guards (NEXTN > 4 rejected), multiple-of-N preflights, block-size clamps (requested k 8 and 16 both ran as 7 in llama.cpp).
- [Measured] Some engines silently drop speculation in their batched path: the native ds4 fork ran 1.0 tokens per step at C2 and above.
- [Measured] `--speculative-attention-mode decode` on SGLang NEXTN cut coding from 62 to 20.97 tok/s; rejected.
- [Measured] Greedy draft sampling regressed DSpark under a sampled target (45.7 -> 42.2 at 8K, 47.4 -> 41.0 at 32K); reverted.
- [Measured] Live traffic contaminates counter deltas; one base pass was discarded. Editing escaped JSON in launch scripts with sed silently did nothing once.
- [Community-measured] An apparent concurrency crossover (DFlash2 slower than no-spec at c8) was a mamba-slot cap at 2 running requests, not a property of speculation (forum 381703, SGLang #36889).
- [Community-measured] Speculation-linked quality regressions that are not numeric noise: TurboQuant KV + MTP or n-gram loops at k = 1 and 3 (vLLM #40831); n-gram at `prompt_lookup_min = 2` corrupting Qwen3-class tool calls in about half of requests, fixed at 8 (vLLM #40875); n-gram changing greedy output 20 / 20 on a repeated prompt (vLLM #41758); DFlash ignoring `repetition_penalty` and looping at accept rate 1.00 (SGLang #28180); mismatched vocabularies decoding garbage (SGLang #24051); junk after EOS on multi-token accepts (SGLang PR #33758); multi-hour windows of exactly 0% MTP acceptance with think-block repetition on SM120 (vLLM #55357); EAGLE acceptance drifting down over hours until restart on H200 (vLLM #41838); wrong answers at concurrency 8 on GB10 (SGLang #36548).
- [Community-measured] Greedy output under speculation is often not bit-identical on quantized targets without the answer changing: a divergence at character 110 traced to batch-shape-dependent GEMM tiling with no drafter involved (madeye); 1 / 20 exact matches with quality preserved (forum 381703); llama.cpp draft-mtp / draft-dspark diverge on Q4 targets but not BF16 while n-gram stays exact (#25618); batched verification alone diverges on CUDA and DFlash2 amplifies it (#27407). vLLM's docs claim lossless "up to the precision limits of hardware numerics". Judge losslessness by answers, not bytes.
- [Community-measured] Graph interactions: MTP + FULL_AND_PIECEWISE deadlock on bonus-token-only steps (vLLM #42271, H20, closed; FULL_DECODE_ONLY did not reproduce); SGLang NEXTN + full decode graph aborted both ranks with invalid-probability asserts and Xid 43 on 2 GB10 while graphs-off passed 52 requests (SGLang #37052); FULL graphs left stale EAGLE draft metadata after position 0 (vLLM PR #38311). On GB10 Hy3 MTP ran ~25% faster eager than with graphs (Marlin W4A16), MiniMax EAGLE-3 in eager cancelled the speculation gain (6.3 vs 7.5 tok/s PIECEWISE), and Qwen3-Coder-Next on SGLang lost ~50% in eager (mirror-only source).
- [Community-measured] Prefix caching and speculation can conflict: EAGLE on SGLang v0.5.16 (TP8, not GB10) cut deep-prompt radix reuse from 97% to 40-53% (SGLang #32459). [Measured] An own vLLM DFlash2 TP2 regression test did not reproduce an acceptance collapse with shared prefixes. See [KV cache and prefix caching](10-kv-cache-and-prefix-caching.md).
- [Community-measured] Stateful n-gram drafters leak across requests: `ngram-cache` fell from 86% to 11% acceptance after a longer request, slower than no speculation (llama.cpp #27852).
- [Community-measured] A community scouting pass claimed no llama.cpp DFlash or DSpark path exists; upstream llama.cpp has DFlash, DFlash2 and DSpark [Code-verified]. Re-read code at a pin before repeating absence claims.
