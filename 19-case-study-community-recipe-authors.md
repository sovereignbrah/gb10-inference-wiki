# Case study: the other DGX Spark recipe authors, what each optimizes and what transfers

Hardware for every number on this page, community or own: NVIDIA GB10 (SM121, compute capability 12.1, 128 GB unified memory), sold as DGX Spark or ASUS Ascent GX10. "1x / 2x / 3x / 4x" is the node count; "TP" is tensor-parallel degree; "C1 / C8" is the number of concurrent requests. Own measurements come from one to three ASUS Ascent GX10 nodes (node-1, node-2, node-3): a two-node pair over one 200G QSFP DAC, and a three-node direct-attach triangle; they are cited by packet date and title. Community authors are named by public handle, and every community number is the author's own measurement under the author's own protocol unless stated. All 46 in-scope repositories were read at their default-branch heads on 2026-09-23 (every pin below equals the head on that date, except where a branch or tag is named); Hugging Face records, NVIDIA developer-forum threads and two X posts were fetched the same day. MiaAI-Lab's own recipes are the subject of [Case study: MiaAI-Lab's DGX Spark recipes](18-case-study-miaai-lab-recipes.md); here they appear only as the substrate or comparator another author used. Two terms recur. The *counting cell* is MiaAI-Lab's structured decode probe (a maximally predictable prompt: count, list, repeat), which several authors quote as a headline. *Matched harness* means the same weights, drafter, fixtures, sampling and timing definition on both arms, with one variable changed.

## 1. What it is

Around forty people and small labs publish "recipes" for running large open models on GB10 boxes: a container image, a launch script, patches, and a table of tokens per second. Each author pushes a different lever. Some make a model fit on one box (memory mapping a 48 GiB table from disk, a memory governor that refuses rather than crashes). Some tune speculative decoding (a small draft model guesses several tokens and the big model checks them in one pass). Some spread a model over three or four boxes and fight the network. Some write kernels (hand-tuned GPU routines) for the GB10's particular chip. A few focus on method: statistical tests before promotion, public withdrawal logs, fully pinned builds. Their headline numbers are not comparable with each other as published, because they are measured with different rulers: a counting prompt or real code, generation that stops at the natural end or is forced to a fixed length, thinking on or off, one box or four, pre- or post-firmware update, wall time or time after the first token. This page catalogs who does what, how to read each author's numbers, which numbers were later corrected (often by the authors themselves), which levers reproduced on the own three-node fleet and which reversed, who builds on whom, and which directions were abandoned. It matters for speed because most levers now running on the own lanes came from these authors: of the community levers re-run here on a matched harness, some reproduced to within 2% (Weschera's single-node C1 42.04 read 41.43 locally [Measured]), some held only on the author's own fixture (a draft depth of 16 ran 144 to 151 tok/s on edit-heavy prompts and 66 on fresh code [Measured]), and some reversed (a two-node vLLM port ran 2.7 to 6.4% slower than the SGLang baseline [Measured]). Related pages: [Speculative decoding on GB10, per engine](02-speculative-decoding.md), [Inter-Spark communication](03-inter-spark-communication.md), [Memory management on a unified-memory GB10](11-memory-on-unified-memory.md), [Profiling protocol](14-profiling-protocol.md), [Engine dispatch maps](16-engine-dispatch-maps.md), [Quality and correctness gates](21-quality-and-correctness-gates.md), [Serving agent workloads](22-serving-agent-workloads.md).

## 2. How each engine does it

This section is organized by engine: which authors ship on it, the mechanism each pushes hardest, and the flags, environment variables and source lines that carry it. Pins are the repository heads read on 2026-09-23.

### vLLM

Most multi-node GB10 recipes are vLLM: Anemll, tonyd2wild, FlyCockpit, jetnet, NNNtrance, fattchris, blazux, pangoleen (Flash-Next), jschmied, nacyot, eugr, timothystewart6, rmagur1203, saifgithub, jeremy-newhouse, luisefigueroa and r0b0tlab. [Code-verified] (READMEs at pinned heads)

- **Anemll, `dspark-vllm-gx10` (2x TP=2, DeepSeek V4 Flash, @081fda97; only release v0.1.1, image `ghcr.io/anemll/dspark-vllm-gx10:0.1.1`).** vLLM 0.25.1 (runtime reports 0.25.2.dev0) with FlashInfer and b12x. Pushes hardest: a bridge from vLLM's DeepSeek V4 runtime to FlashInfer's SM120/SM121 sparse-MLA kernel (a 584-byte packed token envelope; 256-token sliding-window pages split into 64-token views) and a modular b12x MXFP4 MoE backend. Unreleased since v0.1.1: PR #2 (simon-blom, merged 2026-09-03) "DSpark draft SWA cache missing prefix on prefix-cache hit", which produced degenerate output on a prefix hit. Open and unanswered at head: #9 any request with a `tools` array kills the engine (342-byte reproduction), #8 silent freezes after TileLang recompilation, #11 intermittent TP=2 rank divergence on the first DSpark request wedges the GPU, #3 the 0731 checkpoint repeats reasoning until `max_tokens` with MTP=5. [Code-verified] Anemll is listed by some sources as a llama.cpp-family fork; it is a vLLM image. [Code-verified]
- **tonyd2wild (five repositories).** SM121 patch chains that make day-0 checkpoints boot (sparse-attention kpool top-k, a DFlash2 overlay for GLM 5.3 Flash), KV byte pinning and host-memory hygiene, and multi-node topology (TP4 over a switched 200GbE fabric; TP3 with virtual sharding for MiniMax-M3). The 2x GLM image `sm121-v11-dflash2` (2026-08-28) predates the prefix-cache repair #18 (commit 9acb1fbb, 2026-09-16), so agent sessions on the published image re-prefill every turn unless rebuilt (README L140–143 @9fea48c1). [Code-verified] The overlay does not boot at vLLM's default `--gpu-memory-utilization 0.92` on a GB10 pair (108.52 GiB available); the author's 0.85 is required. [Measured] (2026-08-27 "tonyd2wild vLLM DFlash2 B8 on dual DGX Spark") The launcher refuses ModelOpt and abliterated NVFP4 checkpoints after intermittent corrupted token ids (vLLM #54150, open). [Code-verified]
- **FlyCockpit and jetnet (3x, GLM 5.3 Flash NVFP4; FlyCockpit also DeepSeek V4 Flash 3x).** Make non-divisible geometries boot at TP=3: attention heads 64 -> 66, MoE intermediate 2048 -> 2112, drafter GQA 32/8 -> 36/9 or 48/12 (FlyCockpit @8151a5e9). jetnet writes the pad into the on-disk config and adds a selectable NCCL transport (`ib` / `mesh` / `socket`) (@73ffbec4). FlyCockpit's DeepSeek 3x is a thin layer on the Anemll 0.1.1 image with TP=3 + EP + EPLB=2, an NCCL mesh plugin, DSpark MTP=5 and a head pad 72/9 (@5ced1b6c). [Code-verified]
- **blazux, `qwen3.8-Flash-DGX` (1x, Qwen 3.8 Flash-Next, @5be66376).** Official vLLM Flash-Next image plus a patch layer. Pushes hardest: memory fit, by memory-mapping the ~48 GiB per-layer-embedding (PLE) n-gram table from NVMe so ~75 GiB of weights stay resident; a prefix-cache fix (a block-size bug restored all-zero Mamba state); deterministic sparse top-k (jschmied's patch, shipped as patch 8). Default checkpoint switched from RadixArk to NVIDIA's NVFP4 on 2026-09-14. [Code-verified]
- **jschmied, `qwen38-flash-next-gb10` (1x, vLLM nightly + local patches, @6813ea7f).** Checkpoint levers (FP8 dense projections, FP8 `lm_head`), MTP, PLE access pattern, a blockwise-FP8 CTA swizzle for prefill, greedy determinism, and an explicit evidence standard. Upstream edges: vLLM #55180 (blockwise-FP8 CTA swizzle) merged 2026-09-07; #55375 (PLE state-stride fix, authored by peakcrosser7; jschmied root-caused it, filed duplicate #55467 and supplied the evidence) merged 2026-09-05; #58439 (checkpoint-mapped PLE storage) opened 2026-09-23. [Code-verified]
- **fattchris, `qwen-dflash2-spark` (2x TP=2, Qwen 3.8 27B, @cd849160).** A fork of vLLM PR #52816 (z-lab's DFlash2 integration, merged upstream 2026-08-21) with DFlash2 K=16 and a BF16 `lm_head` dequantized from NVFP4, because the candidate selector takes top-K over target logits. [Code-verified] madeye reports that the "unquantized lm_head required" guard lived only in the unmerged PR and is gone in released vLLM 0.28.0, so the BF16-head surgery is no longer mandatory on current vLLM (README L16, L45–52 @a9c6b98e; a code reading, not a measurement). [Community-measured]
- **nacyot, `vllm-ds4f-gb10` (4x TP=4, DeepSeek V4.1 Flash, @5be09c58).** vLLM fork with a disk-tier KV offload and rank-0 relay restore; clocks capped at 2000 MHz. On its `gb10-longctx-offload` branch (@ab7723d3) prefill top-k rebase is disabled at both call sites because it "dropped every non-first prefill request's compressed context" (README L331). [Code-verified]
- **eugr, `spark-vllm-docker` (1x to 8x, @00837c8b; 2,310 stars).** The shared substrate: prebuilt wheels (vLLM 0.29.1rc1.dev467 + FlashInfer 0.7.0, released 2026-09-21), launch-time application of vLLM PRs, a B12X image line, InstantTensor and b12x loaders, an earlyoom monitor, and Dockerfile-level workarounds for upstream regressions. At head the README and image disagree: README L55 says `B12X_AUTOTUNE=0` is the default, while Dockerfile L804 has `# ENV B12X_AUTOTUNE=0` commented out after commit ad4b824a "Re-enable B12X autotune" (2026-09-17). The CUDA-IPC fused path from vLLM #43410 (MiniMax QK RMSNorm) fails when TP spans Spark nodes; eugr first reverted the PR (515895a8, 2026-05-29) and at head disables that path with a targeted patch (Dockerfile L623–626; reason in README L658). [Code-verified]
- **timothystewart6, `vllm-gb10` (@7d6ed700, release v0.30.0-gb10.2 on 2026-09-23).** A fully pinned, reproducible vLLM image; no tok/s claim. [Code-verified]
- **Arch-selection fixes (historical).** saifgithub (vLLM 0.17.2, @7e5cec5a): CUTLASS `enable_sm120_only` traps on `__CUDA_ARCH__ == 1210`; `enable_sm120_family` covers 12.0 and 12.1, and SM121 FP8 had been routed to SM100 tile configs. rmagur1203 (vLLM 0.18.1, @413d945c): CUTLASS shared-memory template fixes (`alignas(1024)` -> `alignas(128)`, exact `ReducedSmemCapacityBytes`, `StageCount<4>`). [Code-verified] Current vLLM covers the family guard. [Interpretation]
- **NVFP4 GEMM backend selection on CC 12.1.** A 2026-03-30 forum report quotes vLLM `nvfp4_utils.py` picking `FLASHINFER_CUTLASS` whenever `has_device_capability(100)` is true, which SM121 satisfies, then logging "Failed to initialize cutlass TMA WS grouped gemm" autotuner skips (forum thread 365119). jeremy-newhouse runs dense GEMM through Marlin (`VLLM_NVFP4_GEMM_BACKEND=marlin`, README L67 @00bb491b) and warns only against the Marlin MoE override. Version-specific; see §7 for the contested measurements. [Community-measured]
- **Flags and env vars that recur in these kits:** `--gpu-memory-utilization`, `--kv-cache-memory-bytes`, `--max-num-batched-tokens`, `--speculative-config` (DFlash2 / MTP depth), `--no-async-scheduling` and `VLLM_PREFIX_CACHE_RETENTION_INTERVAL=0` (Reederey87 v1.1), `VLLM_USE_BREAKABLE_CUDAGRAPH`, `VLLM_NVFP4_GEMM_BACKEND`, `B12X_AUTOTUNE`, `NCCL_IB_HCA`, `NCCL_IB_MERGE_NICS=1`, `NCCL_IB_GID_INDEX`, `NCCL_NET=Mesh` (FlyCockpit), `TP3_HEAD_OVERRIDE=66`.

### SGLang

Single-node Qwen 3.8 27B on GB10 is an SGLang ecosystem: Weschera, hasso5703, darkdatter, pangoleen (27B), sxuff, TysAIs, gitcommit90 and r0b0tlab; plus Tutanka01's GLM NVFP4 2x profiles, scottgl9's fork and beastllama's GLM 2x. [Code-verified] Almost all load RadixArk's NVFP4 export with z-lab's DFlash2 drafter.

- **Draft depth (DFlash2 block).** Weschera ships block 10 (`weschera/qwen38-27b-dflash2:3fad86c`, SGLang 1cf2b8c, @3fad86cb); hasso5703 and pangoleen run depth 16 with maurienne-ai's calibrated NVFP4 draft; darkdatter sweeps 8 to 24 and finds acceptance length peaking at 16 (9.52). [Code-verified]
- **The boot lottery.** FlashInfer autotune draws GEMM tactics at boot, and Weschera reports two identical launches serving about 42 or about 33 tok/s C1, attributing it to "the engine's AutoTuner races seven fp8_gemm kernel candidates" (README L59 @3fad86cb). [Community-measured] Three different answers ship, each code-verified: restart until a probe clears a floor (`scripts/verify_boot.sh`: `MIN_TPS` default 33 at L22, `MAX_ATTEMPTS` 8 at L23, gate test at L44 @3fad86cb); turn autotune off (`run.sh` L128 `--disable-flashinfer-autotune`, directly before `--speculative-algorithm DFLASH`, same launch sets `--mem-fraction-static 0.50`, @81ae2bf5); replay a kept good draw (tactic JSON committed under `data/tactic-cache/<hash>/rank_tp0_pp0_dp0.json`, two hashes, @60639a97, sized by the author at "+16% vs a median boot", README L207). [Code-verified] That these are three answers to one mechanism is [Interpretation].
- **Memory fraction.** 0.85 on first boot (darkdatter; the MiaAI-Lab toolkit), 0.90 shipped by KeyArgo, whose launcher refuses `--mem-fraction-static` at or above 0.95 because it hard-reboots a GB10 during draft-graph capture (`scripts/run.sh` L12, L22–24 @fb3605f9). [Code-verified]
- **scottgl9's fork (@f77232a4).** Routes all NVFP4 GEMM through Marlin W4A16 on the premise that "all CUTLASS FP4 GEMM operations produce corrupt output on SM121"; contested (§7). EAGLE drafts trained on BF16 heads reach ~6% acceptance on an NVFP4 base; `torch._scaled_mm` dispatches an sm89 kernel and is not faster than BF16 at M=1. [Community-measured]
- **GLM on SGLang.** The GLM DFlash capture adapter (#36708, jianc99) merged into PR #36507's feature branch on 2026-08-27, and #36507 merged to main on 2026-09-06. The per-model image `lmsysorg/sglang:glm-5.3-flash-arm64` predated the adapter by 13 hours (beastllama FINDINGS @7025ad23). beastllama found DFlash2-on output not bit-identical to spec-off at temperature 0 (1 of 20 prompts identical; RESULTS.md @7025ad23). [Code-verified] [Community-measured]
- **Known-bad on this hardware.** SGLang silently dropped `lm_head.weight_scale` on the unsloth NVFP4 export (top-1 logprob exactly 0.0, runners-up −29,696, about 6,500x logit inflation). [Measured] (2026-08-19 Qwen 3.8 27B single-node campaign) `--speculative-attention-mode decode`, a lever in the tonyd2wild and scottgl9 lineages, is strongly negative here (§4). [Measured]
- **Other flags that recur:** `--speculative-num-draft-tokens`, `--speculative-token-map` (hasso5703), `--disable-flashinfer-autotune`, `--mem-fraction-static`, `--max-running-requests`, `--cuda-graph-max-bs`, `--chunked-prefill-size`.

### llama.cpp and forks

- **Classification.** Entrpi's `ds4` is a GitHub fork of antirez/ds4 ("DwarfStar"), a standalone C/CUDA DeepSeek V4 Flash engine that loads GGUF weights; it is not llama.cpp. Anemll's image is vLLM (above). [Code-verified]
- **Entrpi `ds4-on-spark` (1x, @99fb7b17) and engine `Entrpi/ds4` (tag v0.6.5 = commit addc0c4b; tag object be6c09b0; head b0a147a7 adds conversation-prefix conditioning).** Native sm_121a CUDA kernels (prefill kernels, continuous batching), disk-persisted KV banks, and a memory governor with virtual banks and measured floors that refuses a request rather than wedging the node. The build is arch-specific: `CUDA_ARCH=sm_121` selects `-gencode arch=compute_121a,code=sm_121a -DDS4_CUDA_HAVE_MXF4=1`; the Makefile comment states that `-arch=sm_121a` alone "silently emits .target sm_121 and ptxas rejects the MMA" (Makefile L38–44 @ tag v0.6.5). The memory floor is `DS4_MEM_FLOOR_GB` (shipped 4 GiB). The DSpark drafter GGUF is by bleysg. v0.6.4 and v0.6.5 add agent robustness (a tool-call protocol reminder past about 30K tokens). xangel82/DS4-GB10-GX10-DSpark-CUDA (@6515ac30) re-vendors Entrpi's CUDA prefill work under MIT attribution (README L533–544). [Code-verified]
- **Speculative verify in ds4.** `docs/MTP_PARITY_GAP.md` (@99fb7b17, last verified 2026-06-03) withdraws the author's own "+35–80% once the kernel lands" projection: single-stream exact MTP verify is a net loss on GB10 (§4), and even at 100% acceptance a step costs 57 ms per token against 51 ms without MTP. Featured numbers are therefore no-MTP; DSpark is the drafter that pays. [Community-measured]
- **llama.cpp proper appears only at the edges of this topic.** vcruz305's GGUF port of incoai's GLM DFlash2 drafter (Hugging Face @caf6ef0c, README L77–91), sxuff's llama.cpp MTP4 / ngram claim (not reproduced on vLLM here, §4), Memoriant's llama.cpp KV-cache study (corrected by its author, §4), and a forum report of a Flash-Next UD-Q4_K_XL GGUF losing coherence near 100K context (thread 381500; anecdotal, no protocol). [Community-measured]

### ExLlamaV3 in vLLM

EXL3 on GB10 is almost entirely derived from MiaAI-Lab's GLM 5.3 Flash kit. [Code-verified]

- **Entrpi, `glm-5.3-flash-exl3-2x-spark` + `vllm-glm-5.3-flash-spark` (2x TP=2, @63f254f7 / @f223ff9f, tier v2.3).** A scheduler and drafter stack on the MiaAI-Lab base: a spec-state ring, a fair mixed-prefill scheduler, an MXFP8 re-quant of the incoai drafter (from local-inference-lab), and b12x FP8 GEMM with per-M dispatch. Issue #3: an `--nfs` head weight load died at about 111 of 120 shards (`NV_ERR_NO_MEMORY`) on the default fused-Trellis path, fixed with `VLLM_EXL3_STANDARD_FUSED=0` plus an eager profile. [Code-verified]
- **Reederey87, `glm53-flash-exl3-2x-dgx-spark` (2x, exllamav3 v1.4.9, @8e443d6b; v1.5.0 on 2026-09-10).** Prefix-cache correctness for hybrid KDA + MLA under agent traffic: 3,584-token pages, a KDA checkpoint only at page-aligned step ends, a drafter prune bug fix, a cache-reset endpoint, a ticket scheduler, and statistical promotion with a Welch test. Its kpool tail-addressing fix (PR #79, 2026-09-20) found "four mutually masking defects". [Code-verified]
- **FlyCockpit, `GLM-5.3-Flash-EXL3-3x-DGX-Sparks` (@9093765c).** MiaAI-Lab image at 3x: an in-kernel Q/out pad from 22 to 32 and a full-width 2048 trellis for routed experts; at util 0.83 a 3,858,012-token pool at 1M context. [Code-verified]
- **outstandly, `glm53-flash-3x-dgx-spark` (3x ring, @87c229eb).** A fork of jakejharris/jspark3 v1.1 (which builds on FlyCockpit's TP3/EP3 work) on the MiaAI-Lab engine image, EXL3 4bpw, a directed QSFP ring (Port0 -> next Port1), MTU 9000, RoCE v2 GID index 3. Commit 944f379e (2026-09-14) ported MiaAI-Lab's E3 grouped fat-expert prefill kernels; on 2026-09-21 the author switched to MiaAI-Lab's official TP3 launcher. [Code-verified]
- **NNNtrance, `GLM-5.3-Flash-EXL3-DGX-Spark` (2x/3x, @7f1bd29c).** A cuda-exl3 fork. Pushes hardest: kernel-dispatch fixes (a TP3-slower-than-TP2 dispatch bug fixed upstream with the kernel author), an NCCL plugin patch so the second cable half carries traffic, a page-counter fix that had been "hiding 45 % of the KV pool" (L8–9), FlashKDA (a port of vLLM #55737, promoted 2026-09-10), and a sparse top-k raise from 2048 to 8192 (promoted 2026-09-12). - **plotarmordev (a GitHub fork of MiaAI-Lab's GLM repo with no own commits; the work lands upstream as PRs #215–#219).** PR #217 "perf(sm121): EXL3 thin-decode fast path (thin-only split from #182)" merged 2026-09-18 (merge ca29e284, head 3421acf0; 17 files, +1523/−6; `overlay/patch_exl3_decode_pipeline.py`, `docs/sm121-perf-paths.md`, GPU parity tests). - **coolbho3k (forum handle emihuang, thread 383583, 2026-09-18).** DeepSeek V4.1 Flash 2x with EXL3 3bpw routed experts and an EXL3 3bpw DSpark drafter, FP4 KV at DCP=2, and a technique that maps the firmware's 2 GB display-reserved memory into CUDA on a headless node (`nvidia_drm modeset=1 fbdev=0`, the DRM buffer registered with CUDA). [Community-measured] No protocolled number (§8).

## 3. What is different on GB10 / SM121

Mechanism owners for this section: fabric and node count [Inter-Spark communication](03-inter-spark-communication.md), memory and the display reserve [Memory on unified memory](11-memory-on-unified-memory.md), clocks and firmware [Clocks, thermal, power](13-clocks-thermal-power.md).

- [Community-measured] **Firmware, driver and kernel version change results by up to 2x, so a GB10 number without them is not comparable.** GX10 firmware OTA2604 (BIOS 0104 -> 0105) doubled upstream ds4 prefill from 385–396 to 805 tok/s and decode from 10.5 to 18.2 at 2,048 context (Entrpi ds4-on-spark issue #16, closed 2026-08-24). A GX10 second ConnectX-7 read as PCIe Gen5 x2 on SoC firmware 0x03000005 and x4 on 0x03000006 (BIOS GX10DGX.0104.2026.0326.1657; forum thread 367853, the reporter's own mea culpa). r0b0tlab measured c=1 decode 38.4 tok/s on driver 580.142 and 11.32 after 580.159.03 (2x TP=2 DeepSeek V4 Flash FP8). Kernel 7.0.0-1019-nvidia breaks NCCL/RoCE `ibv_reg_mr_iova2` with ENOMEM on 2x GB10 while 6.17.0-1032 works (forum thread 383023, 17 posters, a GX10 pair confirmed 2026-09-13).
- [Code-verified] **Arch selection is the recurring build failure.** `sm_121a` must be requested as an explicit gencode pair (Entrpi ds4 Makefile L38–44 @ v0.6.5); a CUTLASS guard written for `== 1200` traps on 1210 (saifgithub); a capability check `>= 100` routes SM121 into SM100-oriented FP4 paths (forum thread 365119).
- [Community-measured] **Unified memory turns memory settings into node-survival settings.** A memory fraction of 0.95 hard-reboots a GB10 during draft-graph capture (KeyArgo); fractions above 0.85 wedged machines during weight load (darkdatter, MiaAI-Lab toolkit); tonyd2wild traced `NV_ERR_NO_MEMORY` deaths to a threshold-triggered page-cache flusher starving the NVIDIA allocator, not to pool size, and withdrew "take vLLM's suggested kv-cache-memory verbatim" (docs/GB10-KV-MEMORY-LADDER.md, superseded 2026-08-29). Process RSS does not see GPU allocations on unified memory (Memoriant CORRECTION-NOTICE, 2026-04-01). [Measured] On the own fleet a 0.95 fraction left too little headroom and 0.90 left 3.4–4.2 GiB (2026-08-21 "Weschera k10 boot-gate YaRN qualification").
- [Community-measured] **Each QSFP port exposes two PCIe halves, and listing one logical HCA per physical port halves NCCL bandwidth.** NCCL 2.30u1 p2p send/recv at 1 GB: 106.5 Gb/s with one HCA per port vs 183.2 Gb/s with both halves, only `NCCL_IB_HCA` changed (tonyd2wild MiniMax-M3 issue #1, OsakaTX; one hardware corroboration by plj5003, one documentation-only by BreBryBro). camerono: all-reduce 1 GiB fp32, 2 ranks, 11.5 with a single HCA vs 24.1 with both halves and `NCCL_IB_MERGE_NICS=1` (unit written "gbps"). [Measured] Own triangle RDMA legs read about 109 Gb/s (2026-09-14 "TP3 triangle first qualification").
- [Interpretation] **The SGLang boot lottery is a GB10-visible effect of autotuned FP8 GEMM tactics on a single small GPU**: at batch 1 one GEMM tactic choice moves the whole decode step. [Measured] On the own node two fresh draws landed within about 1.5% of each other (2026-09-08 "fixed-K10 cache, drafter and chunk screen"), which bounds but does not refute a larger lottery on other hosts.
- [Community-measured] **Single-stream exact MTP verify costs more than it saves on GB10 in ds4** (57 vs 51 ms per token even at 100% acceptance; Entrpi MTP_PARITY_GAP), while vLLM's batched verify on DeepSeek is net-positive per the same document. Speculation pays through cheap drafters and depth, not through exact verify on one stream.
- [Code-verified] **Three-node tensor parallelism needs geometry padding.** GLM 5.3 Flash has 64 attention heads, not divisible by 3; the community pads to 66 (FlyCockpit, jetnet, localaiguyy), with matching pads for the MoE intermediate (2048 -> 2112) and the drafter (32/8 -> 36/9 or 48/12). [Measured] The own triangle booted with heads padded to 66, and an abliteration donor had to be padded the same way (2026-09-14 "TP3 triangle first qualification").
- [Measured] **Direct-attach topology constrains node count.** Four nodes need a switch or a ring relay (tonyd2wild's TP4 is switched; luxingcom and nacyot use rings). On a three-node triangle where two of three legs are same-index ports, NCCL qualified with cuMem enabled and a per-rank ring graph, so outstandly's directed-ring cabling rule was not required on the own stack (2026-09-14 "TP3 triangle first qualification").
- [Community-measured] **A "TP=2" number can silently be a one-box number.** A forum MiniMax report says that skipping the Ray head's delay lets vLLM fall back to a single GPU and OOM (thread 375022).
- [Community-measured] **Headless nodes carry a 2 GB display-reserved region** that one author maps into CUDA; a second user reports +250K KV tokens on a GLM recipe with no decode change (forum thread 383583). A standalone probe with a control reads the reclaimed pool at 162 GB/s read / 114 GB/s write vs 235 / 196 GB/s for `cudaMalloc` memory, about 69% (MiaAI-Lab GLM kit PR #234; see [Memory on unified memory](11-memory-on-unified-memory.md)).

## 5. Levers, ranked

Ranked by expected transfer to a GB10 deployment like the own fleet (single-node Qwen, two-node DeepSeek, three-node GLM), weighing evidence strength against cost. Each lever names the author it came from, the topic page it belongs to, and the smallest experiment that would falsify it.

1. **Tune draft depth on real-shaped work, never on the counting cell** (Weschera, darkdatter, fattchris; own k=3 vs k=7). Applies to: every engine with DFlash2 or DSpark x Qwen 27B, GLM 5.3 Flash, DeepSeek V4 x 1x to 3x. Gain: +14.6% code / +7.0% prose moving block 8 -> 10 on one node [Measured] (4a-2); +31 to +38% decode at 64K depth moving k=7 -> 3 on two nodes while the counting cell fell 41% [Measured] (4a-15); depth is not monotone in any author's sweep (fattchris K=24 < K=16, darkdatter acceptance peaks at 16, Weschera block 12 at 29.7 < block 10) [Community-measured]. Cost: one boot per depth. Risk: a depth tuned for code can lose on prose and at concurrency (packed-head k=8 beat BF16-head k=16 on prose by 28%, 4a-5). Falsify: a depth sweep (at least three depths) on fixed code, prose and 64K fixtures with C1 and C4; if the winning depth does not beat the incumbent on at least two of three real-shaped cells, drop it. See [Speculative decoding on GB10, per engine](02-speculative-decoding.md).
2. **Calibrated NVFP4 DFlash2 draft** (maurienne-ai, via pangoleen and hasso5703). Applies to: SGLang x Qwen 3.8 27B x 1x. Gain: +6.7% code / +4.1% prose at K10 [Measured] (4a-18); a second screen arm read +6.5% / +14.6% [Measured] (2026-09-08 "Orca NVFP4 exports screen"). Cost: a drafter swap, one boot. Risk: quality and long-context behavior unverified; FP8-quantizing the draft instead lost 16% for Weschera [Community-measured] (4b-14). Falsify: three boots per arm on the fixed harness plus full-context retrieval, strict JSON and a soak; if the gain falls inside boot-to-boot spread, reject. See [Speculative decoding](02-speculative-decoding.md).
3. **Community TP3 geometry plus the three-node move** (FlyCockpit, jetnet, outstandly, NNNtrance). Applies to: vLLM + EXL3 or NVFP4 x GLM 5.3 Flash x 3x. Gain: outstandly TP3 over TP2 on the same boxes, prose 33 -> 41 (+24%) and code 45 -> 51–56 (+13 to +24%); the structured 73 -> 95 (+30%) is a counting cell [Community-measured] (4b-20); own triangle within about 8% of outstandly on the counting cell and with an identical pool on the official launcher [Measured] (4a-19, 4a-20). Cost: a third node and a head/MoE/drafter pad. Risk: donor checkpoints (abliteration, drafter) need matching pads; expert parallel on NVFP4 frees no memory and is wash-to-worse [Community-measured] (4b-19). Falsify: same fixtures TP2 vs TP3 on the same weights; if prose and code do not gain at least 15% over TP2, the third node is not paying. See [Inter-Spark communication](03-inter-spark-communication.md).
4. **Address both PCIe halves of each QSFP port** (camerono, tonyd2wild issue #1). Applies to: NCCL x any model x 2x and up. Gain: 106.5 -> 183.2 Gb/s p2p and 11.5 -> 24.1 all-reduce [Community-measured] (4b-47, 4c-8); own configuration applied on the DeepSeek pair with performance not measured [Historical diagnostic] (config only). ## 6. Protocol

This is the protocol an agent runs to transfer one community lever (an image, a recipe, a flag, a drafter, an export, a kernel) onto a GB10 lane. It is grounded in §4: the reproductions that held (4a-1, 4a-12), the ones that held only on the author's fixture (4a-4), the ones that reversed (4a-7, 4a-23) and the ones that passed speed and failed correctness (4a-14, 4a-31, 4a-32). See also [Profiling protocol](14-profiling-protocol.md) and [Quality and correctness gates](21-quality-and-correctness-gates.md).

**Preconditions (fleet rules, all mandatory).**
- No memory overcommit: at least 8 GiB MemAvailable on every rank before a start, and a warm floor of at least 5 GiB on every rank after the longest qualified prefill. Never copy an author's memory fraction, KV byte pin or rightsize step; derive it on this host (4a-3, 4a-8; one copied rightsize-plus-pin step starved a node until a power cycle [Historical diagnostic]).
- One variable per boot. KV pin raises are at most 1.5 GiB per boot; a change that frees memory and one that spends it are two boots.
- Stop traffic when MemAvailable falls below 4 GiB on any rank.
- Clean window: no co-tenant GPU work, builds or other benchmarks; the lane's owner has agreed to the downtime.
- Restart A/Bs with the image and recipe pull skipped, so both arms run identical bits except the variable.
- Never restart a serving gateway or front-end as part of the experiment; if the lever needs one, stop and hand that step to the operator.
- All [entry-page](README.md) rules apply, in particular: greedy logprob probe after every relaunch; discard the first request and warm every shape; unique nonce at token 0 with zero cached tokens asserted from the usage block; every rank at the same clock cap with no latched rank; the selection line on every rank; ≥3 reps with a closing A/B/A; MemAvailable every 1-2 s and zero NV_ERR_NO_MEMORY/Xid; no reboot without per-node permission. For this page that means in particular the selection line on every rank, the same clock cap on every rank, warm shapes, a nonce per prompt, a closing A/B/A, and no reboot or kernel command-line change borrowed from a recipe without per-node permission.
- Record firmware (BIOS and SoC), driver and kernel versions for every node before the first boot (§3: each has moved GB10 results by up to 2x).

**Step 1. Read the claim before touching a node.** Write down, for the exact number being transferred:
- topology and TP degree of that row (4c-1: a TP4 row circulated as TP2);
- fixture: counting cell, edit-heavy, fresh code, prose, depth; measured input/output token counts, not the nominal ones (4a-1: "512/2048" measured 173/560);
- EOS mode: natural EOS, `max_tokens` cap, or forced length with ignore_eos (4b-40: EOS-terminated short runs under-report by 25–275% at depth and concurrency; 4c-11: ignore_eos can add post-EOS filler);
- thinking on or off, sampling temperature, draft depth, slots and concurrency;
- timing definition: wall, net of TTFT, post-first-token (llama-benchy tg), or SSE-chunk count (4c-12, 4c-20);
- baseline type: same boxes and same day, the author's previous runtime, or another lab's published figure (4b-5, 4b-18 compare against published cross-lab numbers);
- date against the author's corrections (4c-5 to 4c-23) and against the current release (4c-3).
A claim missing any of these is a pointer to a mechanism, never a prior for the expected gain (jschmied's stated rule, notes/closed-levers.md @6813ea7f).

**Step 2. Deduplicate lineage.** Compare image digest and weight hashes against every other report used as corroboration; two reports on the same bytes are one report (§5 collaboration graph).

**Step 3. Correctness before speed.** On the candidate build: a logprob sanity probe (catches dropped head scales, 4a-32), prompt-length truncation check (4a-27), deep retrieval at the served context, strict JSON, a multi-turn tool loop, and output equality on a prefix-cache hit vs cold (Anemll PR #2). A candidate that fails any gate is rejected whatever its speed (4a-14, 4a-31).

**Step 4. Reproduce the author's number on the author's fixture.** Run the author's own script and fixture unmodified, three to five runs. Within about 5% of the claim means the build is the one the author measured; a large miss means the build, firmware or ruler differs and later A/Bs are not comparable to the claim.

**Step 5. Matched-harness A/B.** Same weights, drafter, fixtures, sampling, timing and slots; exactly one variable changed. Cells: fresh code, prose, a 64K-depth cell, C1 and the lane's working concurrency (C4 or C8), plus a cold long-context prefill. Never rank on the counting cell (4a-15). At least two boots per arm for any decode comparison (boot-to-boot variance, see [Profiling protocol](14-profiling-protocol.md) lever 11); at least five matched repeats for a claimed gain under 10%; at least 30 runs with a histogram for any lever with a reported bimodal distribution (4b-35).

**Record (packet fields).** Author handle, repository and pin; the claim quoted with its protocol; what differs between the author's setup and this one; firmware, driver, kernel, engine version and image digest; weight and drafter hashes; the one-line diff; memory settings derived on this host; per-cell tok/s with trials and spread; acceptance per cell; TTFT and cold prefill; per-rank MemAvailable minimum; correctness-gate results; Step 4 reproduction result; verdict (confirmed / contradicted / confirmed-on-author-fixture-only / untried) and the topic page it feeds.

**Pass gate.**
- Step 3 gates all pass.
- The matched A/B beats the incumbent outside run-to-run spread on at least two real-shaped cells, and loses no cell by more than 3% (a win on code that loses prose, like 4a-4 vs 4a-5, is a profile, not a default).
- Warm floor at least 5 GiB on every rank through the longest qualified prefill; no `NV_ERR_NO_MEMORY`.
- For bundles, each component is either isolated or recorded as "adopted inside a bundle, attribution unmeasured" (4a-21).

**Rollback.** Revert the one change (image tag, flag, drafter or export pin) to the recorded incumbent, boot with the pull skipped, and confirm the incumbent's cells and pool return to their recorded values. Keep the failed attempt's packet; a failed transfer is a §7 entry, not a deleted run. Remove any flag inherited from a community kit that has no provenance line and no A/B (two such flags ran unmeasured here until noticed [Historical diagnostic]).

## 7. Anti-patterns and known-bad

Mechanism owners for this section: correctness [Quality and correctness gates](21-quality-and-correctness-gates.md), speculation [Speculative decoding](02-speculative-decoding.md), memory [Memory on unified memory](11-memory-on-unified-memory.md), fabric [Inter-Spark communication](03-inter-spark-communication.md), MoE [MoE dispatch](08-moe-dispatch.md).

- [Measured] **Ranking authors on the counting cell.** Changing only draft depth 7 -> 3 moved the counting cell 60.86 -> 35.97 while 64K-depth decode rose 31–38% (4a-15). Entrpi's 74.7, FlyCockpit's 64.3 / 74.9, Reederey87's ~74 and outstandly's 95 structured all rank prompt predictability at a given depth, not serving speed.
- [Historical diagnostic] **Relabelled numbers in circulation**: a TP4 row quoted as TP2, a BF16-KV control quoted as the headline, a v1.0.0 README quoted ten releases later, a 256-token ignore_eos ceiling, a k=64 attractor on non-GB10 hardware, a quality score quoted as tok/s, degenerate count-to-300 peaks (4c-1 to 4c-4).
- [Measured] **Accepting a speed win from a build that fails correctness.** A one-node EXL3 DeepSeek build reproduced the published speed and scored 0/7 on a strict agent loop (4a-14); an export that put attention and GDN layers in FP4 ran 20% faster and failed strict JSON on every retrieval probe (4a-31); SGLang silently dropped an `lm_head` scale on a public NVFP4 export (4a-32); a repack shipped a tokenizer that truncated prompts at 8,192 tokens (4a-27).
- [Community-measured] **Silent corruption shipped in public artifacts.** LibertAIDAI and abliterated ModelOpt NVFP4 builds emit intermittent corrupted token ids (vLLM #54150, open); a Blackfrost config declares W4A4 NVFP4 with zero input_scale tensors and garbles unless rewritten to W4A16; tonyd2wild's dealignai o_proj transplant collapsed draft acceptance to 0.224 (2.57 tokens/step, position 7 at zero) and was retired (4x README L80–94 @2ac4e8dd); NNNtrance found a gate/up global-scale header defect in two of four measured public NVFP4 checkpoints (docs/13 @eb11cef2); a widened SM121 TensorRT-LLM sparse-decode guard emitted token id 0 at 120K–210K [Historical diagnostic].
- [Community-measured] **Withdrawn profiles.** hellojiaru withdrew a dual-GB10 Flash-Next NVFP4 NEXTN/EAGLE profile after real multi-turn traffic produced invalid sampling probabilities, a device-side assert and Xid 43 on both ranks at ~29K and ~50.6K context, with CUDA graphs and overlap already off (withdrawal advisory @b1394ae7). - [Community-measured] **Copying memory settings across hosts.** 0.95 fractions hard-reboot at draft-graph capture (KeyArgo) or leave too little headroom (4a-3); above 0.85 wedged machines during weight load (darkdatter, MiaAI-Lab toolkit); sfxnz's KV pins at 5.0 GiB ran ~20% slower and at 5.14 GiB crashed under load (4b-49); a dequant-once approach for the quantized-head selector hard-reboots at graph capture (TysAIs README L88); tonyd2wild withdrew "take vLLM's suggested kv-cache-memory verbatim". [Measured] The vLLM default 0.92 refused to boot a two-node overlay (4a-8).
- [Measured] **Speculative verify and attention modes that look free.** `--speculative-attention-mode decode` dropped coding 62 -> 21 tok/s (4a-23); greedy draft sampling cost 8–14% on the DeepSeek pair (4a-13); MTP4 lost 6–7% on essays and C8 (4a-24).
